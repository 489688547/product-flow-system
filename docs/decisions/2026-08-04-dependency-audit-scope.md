# 依赖审计只对生产依赖设硬门槛

## 状态

已实施，2026-08-04。

## 背景

`npm audit --audit-level=low` 覆盖全部依赖，2026-08-04 因为新公告开始失败，
**堵住了所有 PR**——包括与依赖无关的改动（当时被挡的是一个 shell 脚本）。

逐条看这 5 个漏洞：

| 包 | 位置 | 可否无损修复 |
|---|---|---|
| postcss | **生产依赖** | 可以，已修 |
| brace-expansion | 开发依赖 | 可以，已修 |
| undici / miniflare / wrangler | 开发依赖 | **不能** |

后三个是同一条链：公告把 `wrangler >= 4.36.0` 全部标记为受影响，唯一的「修复」是降到
`4.35.0`——从当前的 `4.112.0` 倒退 77 个版本。wrangler 是本地 CLI（D1 操作、本地
调试），倒退这么多版本的风险远大于它要防的问题。

## 决策

审计分两档：

```
npm audit --omit=dev --audit-level=low   # 生产依赖：low 以上一律拦下，硬门槛
npm audit --audit-level=high || true     # 全部依赖：高危仍打印出来，但不拦
```

**生产依赖的门槛没有放松**，仍是 low。放松的只有开发依赖，而且高危仍会打印在 CI 日志里
——不是让它消失，是不让它挡住无关的改动。

## 为什么不选另外两条路

- **降级 wrangler**：倒退 77 个版本，D1 命令行是日常运维在用的，风险更大。
- **加白名单忽略特定公告**：白名单会一直留在那里，等 wrangler 修好了也不会有人去清，
  下一个真问题反而可能被同一条白名单盖住。分档是按「这个依赖会不会进部署产物」划的，
  不针对某个公告，不会过期。

## 复查条件

wrangler 发布不受该公告影响的版本后，把 `--audit-level=high || true` 那一档收回 low。
