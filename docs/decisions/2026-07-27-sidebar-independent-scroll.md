# ADR：侧栏独立滚动，水平裁剪统一使用 overflow-x: clip

## 状态

已接受，2026-07-27。

本决策取代 `b7267ea`「侧栏改为随文档流伸展，取消独立滚动」的布局方式，并保留 `cbdd44b`
关于滚轮接力的边界（侧栏滚到底后滚轮量必须交还页面）。

## 背景

左右两栏共用同一个文档滚动条时，切换导航会同时移动两栏。`showScreen` 在切换页面后调用
`window.scrollTo(0, 0)` 让主工作区回到顶部，这个动作把刚被点击的导航项一并甩离原位置，
指针和视线失去锚点。在 1440×900 下实测位移达 1600px。

排查中发现两个被掩盖的问题：

- `html, body { overflow-x: hidden }` 与 `main { overflow-x: hidden }` 使这些元素成为滚动
  容器，令其后代的 `position: sticky` 静默失效。`.topbar` 的吸顶因此一直没有生效，属既有缺陷。
- 分组展开状态只增不减并本地持久保留，使用一段时间后所有业务分组同时展开，侧栏高度远超一屏，
  放大了上述位移的可见幅度。

「右侧切换后回到顶部」与「左侧导航保持不动」在共用滚动条的前提下不可兼得，必须拆分滚动容器。

## 决策

- 侧栏使用 `position: sticky; height: 100dvh`，品牌区固定，导航区在自身内部滚动。切换页面时
  `window.scrollTo(0, 0)` 只作用于主工作区，导航保持原位。
- 侧栏导航不使用 `overscroll-behavior: contain`，滚到底后滚轮量继续接力给页面。
- 水平裁剪一律使用 `overflow-x: clip`，不使用 `hidden`。`clip` 同样裁剪溢出内容，但不创建滚动
  容器，因此不破坏后代的 `position: sticky`。
- 分组展开改为手风琴：进入某个业务 App 的任一页面时只保留该分组展开并收起其余分组，
  用户手动展开的分组在下次进入其他业务 App 之前保持不变。
- 路由切换后对激活项执行 `scrollIntoView({ block: "nearest" })`，覆盖深链接进入的场景；
  `nearest` 在元素已可见时不产生位移，正常点击不会跳动。

## 边界与代价

- `overflow-x: clip` 需要 Chrome 90+、Firefox 81+、Safari 16+。若钉钉内嵌 WebView 低于该
  版本，回退方式是把水平裁剪移到 `.app-shell` 上，而不是改回 `hidden`。
- 放弃 `b7267ea` 追求的「导航项全部平铺可见」。手风琴把侧栏高度压到接近一屏，但企业账号的
  折叠态基线约 17 项（公司经营 7 项与平台 4 项不可折叠），1080p 下仍可能轻微溢出，
  内部滚动条不会完全消失。
- 手动展开 A 组后导航到 B 组，A 会被收起。这是控制侧栏高度的必要代价。

## 验证

在加载真实 `src/styles.css` 的独立布局验证页中实测（1440×900）：激活项位移由 1600px 降为 0，
主工作区正常回到顶部，侧栏内部滚动位置保持，顶栏恢复吸顶，插入 4000px 宽元素后仍无横向滚动条。

回归断言位于 `react-tests/brand-content-visual.test.mjs`，同时守护 sticky 布局、
`overflow-x: clip` 与「不得重新引入 `overscroll-behavior: contain`」三项。

尚未在钉钉内嵌 WebView 中验证。

## 结果

导航锚点在页面切换时稳定，顶栏吸顶恢复。`overflow-x: hidden` 破坏 sticky 是一类容易复发且
难以定位的缺陷——它不报错、只是让吸顶悄悄失效，因此以断言而非注释固化。
