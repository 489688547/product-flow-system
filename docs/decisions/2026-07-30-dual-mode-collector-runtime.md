# ADR：网页采集器采用正式与实验双模式

## 状态

已接受，2026-07-30。

## 背景

公司网页采集已经具备固定 Provider 适配器、公司 Chrome 登录态、本机文件处理、任务租约、检查点
和受控事实入库。固定适配器适合正式经营数据，但新页面和临时需求需要修改代码才能验证。公司希望
借鉴 EasySpider 的任务图和本机脚本能力，同时准备把控制面从 Cloudflare 迁往阿里云。

## 决策

扩展现有 `web-collection`，增加 `formal` 与 `experimental` 双模式，不引入第二套任务系统，也不
复制 EasySpider 的 AGPL 源码。

- `formal` 仅执行 Provider 注册的页面、动作、选择器、解析器和质量规则，完整成功后可写正式事实。
- `experimental` 允许总经办和数据管理员运行页面 JavaScript、本机 Python、系统命令、条件、循环、
  变量和多候选选择器，结果先写本机 SQLite 并标记 `untrusted`。
- 实验结果通过明确校验后成为 `validated`；只有发布为正式模板并重新完整执行才能生成 `trusted`。
- 公司 Chrome、登录态、下载和脚本执行留在公司 Mac；控制面、数据库、日志和告警可以从 Cloudflare
  迁往阿里云。
- Runner 只依赖版本化 HTTP 契约和设备身份，不识别 D1 binding、SQLite/PostgreSQL 数据库或 OSS。

## 安全与权限

内部使用不取消身份、设备和审计边界。自由脚本只能由已授权角色创建和执行；执行包绑定 Runner、
模板版本、内容哈希和短期有效期。脚本在固定工作目录和专用操作系统用户下运行，受超时、输出、
子进程、文件和循环限制，不继承数据库 Secret。实验执行器不能直接写正式业务数据库。

验证码破解与反检测可以作为默认关闭、可审计的实验选项，但不得自动进入正式模板。登录态、Cookie、
Token、验证码、完整页面正文和客户信息不得上传控制面。

## 兼容与迁移

没有模板字段的现有任务继续使用当前 Provider 适配器。实验能力默认关闭，关闭双端开关即可回滚，
不影响现有快麦和抖店任务。阿里云迁移使用相同 API、错误码和存储接口契约；迁移完成前阿里云状态
保持 `integrating`，Cloudflare 继续是已连接控制面。

## 后果

新页面和文件处理可以先在本机快速试验，再通过版本化模板和质量规则升级为正式采集。代价是 Runner
需要管理脚本进程、资源限制、本机 SQLite 和更细的审计；服务端需要增加模板版本、运行与签名执行包
契约。首期不建设可视化拖拽编排器，避免在执行协议稳定前增加第二个复杂产品面。
