# 商品主数据销售编码治理实现计划

## 数据与迁移

1. 新增 `product_catalog_sales_mappings`，保存销售编码、目标商品、启用状态、版本和更新身份。
2. 新增 `product_catalog_sales_mapping_audit`，追加保存创建、替换和撤销事件，不保存凭据或原始 Provider 响应。
3. 为销售编码唯一性、目标商品和审计时间建立索引。
4. 更新环境能力清单、展示数据策略和迁移证据；回滚方式为停用映射读取并删除新增表。

## 领域与 API

1. 扩展销售聚合器：
   - 支持人工映射；
   - 输出按销售编码汇总的未匹配明细；
   - 保留编码 × 平台行数；
   - 对 SKU 冲突失败关闭。
2. 扩展商品目录 GET，返回映射和当前查询范围的未匹配明细。
3. 新增 `/api/platform/v1/product-catalog/sales-mappings`：
   - `POST` 创建或替换映射；
   - `DELETE` 撤销映射；
   - 使用商品目录编辑权限；
   - 校验商品存在、销售编码非空和版本冲突。
4. 更新 API 契约、集成注册表和环境能力文档。

## 前端

1. 删除页面身份标签和库存单位指标。
2. 修正商品问题规则及组合品成本计算。
3. 调整任务视图和表格术语。
4. 新增未匹配销售编码弹窗。
5. Provider 增加保存、撤销映射和刷新当前经营范围的方法。
6. 未归属销售警告改为 ERP 商品完整性优先流程：主操作打开商品文件导入，成功后沿现有 Provider 刷新自动重算；人工映射默认收起。
7. 组合品展示分类固定为“组合品”；列表和详情统一调用领域成本函数，按当前子 SKU 成本与数量汇总。

## 测试

1. 领域测试：组合品结构、展示分类、当前子 SKU 成本汇总、成本缺失、映射聚合、未匹配明细和冲突。
2. API 测试：读取、创建、替换、撤销、权限和并发版本。
3. UI 测试：文案、列名、弹窗、空态、错误态和禁用态。
4. 运行治理、集成、环境能力、全量测试和构建。
5. 使用本地沙箱验证写入，使用真实只读数据验证组合品展示和未匹配数量。

## 发布与回滚

本轮仅本地验收，不提交、不合并、不部署。后续获得发布指令后，先从最新 `main` 更新分支并跑完整 Definition of Done。API 可通过停止前端调用和忽略映射表快速回滚；新增表保留审计数据，不在回滚中破坏性删除。
