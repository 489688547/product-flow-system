# 商品主数据销售编码治理设计

## 页面结构

### 顶部指标

依次显示：

1. 商品；
2. 有销量商品；
3. ERP 商品数据可能不完整；
4. 最近同步状态。

“最近同步状态”同时展示商品档案和销售事实的最新时间。“ERP 商品数据可能不完整”指标可点击查看诊断明细；页面警告的主按钮是“从 Chrome 重新获取商品”。

### 任务视图

- 全部商品；
- 资料待补充；
- 组合品；
- 未售商品；
- 未关联产品。

“资料待补充”使用具体原因标签：缺少规格、缺少规格编码、缺少组成关系、缺少分类、缺少品牌。

### 商品表格

- 商品：名称、主商家编码。
- SKU / 组成：
  - 单品显示主要规格编码和规格数；
  - 组合品显示组成项数，摘要展示组件编码和数量。
- 类型、分类和产品关联状态放在对应表格列头筛选，不占用上方查询区。
- 类型 / 组成：显示单品或组合品；组合品补充组成数量。
- 分类 / 品牌：组合品分类固定显示“组合品”，单品显示 ERP 分类。
- 销量 / 净销售额：支持销量与销售额升降序，默认“销售额 高→低”。
- 成本：
  - 单品显示规格成本范围；
  - 组合品只读取当前组件 SKU 成本并按数量汇总；
  - 无法可靠计算时显示缺失原因。
- 状态 / 操作。

## 销售数据未找到商品弹窗

弹窗顶部先提供“导入最新 ERP 商品文件”，说明导入后会自动重新核对当前销售归属；搜索和异常明细位于其后，表格一行代表一个销售编码：

- 销售编码；
- 销售标题；
- 涉及平台；
- 销售数量；
- 净销售额；
- 最新业务日期；
- 关联商品；
- 操作。

手工关联默认收起，并明确标记“确认是历史销售别名后再手工关联”。展开后支持按商品名称、主商家编码搜索。保存期间禁用重复操作；成功后保留弹窗并刷新结果。空态说明当前日期范围内没有待匹配编码。错误态保留用户输入并提供重试。

已有商品/SKU 同码时由系统自动归属，不进入弹窗。若编码只出现在组合品的子 SKU 中，弹窗明确提示“缺少单品档案，不会自动归到组合品”；只有确认编码是已有商品的历史销售别名时，用户才执行人工关联。

## 交互与可访问性

1. 警告卡使用按钮语义并可键盘触发。
2. 弹窗打开后焦点进入标题，关闭后返回触发按钮。
3. 输入、选择、保存和撤销都有可见焦点、禁用态和错误反馈。
4. 金额、数量和日期不只用颜色表达状态。
5. 1280px 笔记本宽度下表格允许横向滚动，关键身份列保持可读。

## 组合品模型

组合品展示两层身份：

- 商品层：商品名称、主商家编码；
- 组成层：组件 SKU 编码与数量。

组合品不要求拥有独立库存 SKU。有组成关系即为结构完整；商品名称、编码格式或编码长度不得用于推断组成关系。

组合品详情逐项展示子 SKU、每套数量、当前 SKU 单位成本和组件成本小计，底部显示组合成本。只要任一组件缺少当前 SKU 成本，组合总成本显示“成本不完整”，不展示部分合计。
