# 抖音接口采集 PRD

## 文档状态

- 状态：开发中
- 负责人：数据中心
- 最近更新：2026-07-29

## 背景与问题

抖店采集每天失败。48 个任务中 `DOUYIN_DATE_RANGE_NOT_APPLIED` 与
`DOUYIN_DATE_CONTROL_MISSING` 合计 15 次，占全部失败的 45%，是采集失败率
59% 的最大单一来源。

根因是罗盘的日期组件只响应 `isTrusted` 事件，而扩展没有 `debugger` 权限，
无法派发可信事件；写入 `input.value` 页面也不接受。详见 `findings.md`。

按 DOM 路线修复的尝试已回滚（#159 → #160）：它让校验通过但页面筛选未变，
会静默采集错误日期范围的数据，比明确失败更危险。

## 目标

- 抖店四类资源改为直接请求罗盘自身使用的同源接口，按业务日取数
- 消除因页面结构与事件可信度导致的日期失败
- 接口不可用时给出明确、可区分的失败信号，不产生静默错数据

## 非目标

- 不改变四类资源的标准事实字段与入库链路
- 不申请扩展的 `debugger` 权限
- 不接入抖音开放平台 API（属独立评估）
- 不改变快麦侧的任何采集逻辑

## 用户与权限

采集在公司 Mac 的 Chrome 中以员工既有登录态运行，鉴权仅依赖 Cookie。
扩展不读取、不存储、不上传任何凭据。

## 业务规则

- 只登记页面实际请求过的接口路径。未经生产验证的路径不得进入清单
- 请求不携带一次性签名参数与埋点 ID
- 成功判据为 `st === 0` **且** 响应含非空数据；仅 `st === 0` 不足以判定成功
- 登录失效、风控拒绝、空数据、结构异常各有独立错误码，便于区分处理方式

## 异常与边界

- 风控拒绝：`DOUYIN_API_RISK_CONTROL`，可稍后重试
- 登录失效：`DOUYIN_LOGIN_REQUIRED`，需人工登录后再触发
- 成功但无数据：`DOUYIN_API_EMPTY_DATA`，多为接口路径或参数不被接受
- 响应结构异常：`DOUYIN_API_MALFORMED`，内部接口无契约保证，需人工确认

## 验收标准

- 四类资源的接口清单全部经生产验证可取数
- 同一接口对不同业务日返回不同数据
- 不存在的接口路径必须被判为失败而不是「当天无数据」
- 单元测试覆盖全部四类失败信号

## 上线与回滚

接口采集与既有 DOM 采集互不依赖，可按资源类型分批启用；
出现问题时回退到导入官方报表的既有兜底路径。
