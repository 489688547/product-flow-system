# 抖店罗盘经营数据采集设计

## 用户任务

数据负责人需要确认抖店昨天四类经营数据是否完整入库，并在失败时知道由谁、在哪台设备、执行什么恢复动作。老板和运营只消费数据库事实，不进入抖店逐项抄数。

## 信息层级

- 主信息：昨天四类资源是否就绪、数据截止日、覆盖率、行数、最后可信日期。
- 辅助信息：店铺、任务阶段、完成时间、来源版本、错误和恢复动作。
- 低频信息：attempt、schema/selector version、文件哈希、历史运行。
- 永不展示：凭据、Cookie、Token、验证码、完整页面、原始文件、绝对路径、客户个人信息。

## 页面结构

- 不新增导航。
- “数据接入 → 电商平台”删除重复的全局摘要/刷新块。抖音卡片只显示平台、已登记店铺名称、店铺 ID 和“添加”；adapter readiness、资源进度和恢复动作只在“数据同步”呈现。
- “数据同步”复用现有设备、异常优先、执行记录和恢复动作，增加四个抖店资源。
- 业务 App 通过 `/api/platform/v1/commerce-facts` 查询事实，不直接调用插件或抖店。
- 巨量千川保持独立的未接入广告平台卡片。

## 交互流程

### 日常成功

数据负责人可先用“添加”登记店铺名称和店铺 ID；重复 ID 幂等更新名称。首次运行时，插件在固定店铺管理页识别稳定店铺 ID 和店铺名，服务端核对或更新目录后生成四个任务；公司 Mac 依次领取、下载或安全读取、归档、解析、提交。页面逐资源显示完成时间、行数、覆盖率、可信等级和最新日期。

### 多店铺与登录隔离

不同账号分别使用独立 Chrome Profile，不使用多个无痕标签隔离 Cookie。同一账号可切换的多个店铺共用 Profile。扩展把最近在固定店铺管理页识别出的店铺 ID 保存在当前 Profile 的扩展存储中，并在领取任务时提交；控制面只返回该店铺的抖音任务，Kuaimai 等无店铺任务保持兼容。任务执行前仍校验固定 Provider、资源、域名和店铺身份，不匹配时停止采集。

### 部分就绪

四类资源独立呈现。商品成功但直播失败时整体为“部分就绪”，业务 App 不补齐失败资源；上一可信直播批次仍可读，并明确当前请求日期状态。

### 人工恢复

任务进入 `waiting_human` 后显示“打开抖店处理”。员工在公司 Mac 同一 Chrome Profile 完成登录或验证，再点击“我已处理，重新采集”；系统重排原店铺、资源和业务日，不创建自由 URL 或 selector。

## 组件复用

- 复用 MV3 的设备身份、alarms、downloads、本机桥接和严格任务投影。
- 店铺自动发现也通过同一配对桥：扩展只提交固定 `providerId/storeId/storeName`，服务端持有店铺目录。
- 店铺手工登记复用同一服务端目录和校验函数，由已授权会话执行；浏览器不得直接写 D1。
- 复用网页采集控制面的 job/run/cursor/runner/notification。
- 复用数据同步页的状态徽标、执行记录、异常优先和设备卡片。
- 复用业务数据库选择中间件、流式 XLSX/CSV 解析和显示数据目录。
- 高触达的 Kuaimai content script 和本机下载处理器先抽出 provider executor/processor 接口，再接入 Douyin。

## 页面状态

- 加载：读取 runner 心跳、四资源任务、游标和质量。
- 尚未运行：明确“尚未到今日计划时间”或“尚未完成真实验收”。
- 官方无记录：显示 0 行且高可信，不显示错误。
- 设备离线：给出公司 Mac 和启动采集器动作。
- 未登录/人工验证：显示同一 Profile 的恢复动作。
- 页面变化：显示“等待适配”，停止写入。
- 无权限：可查看安全摘要，不能重试或启停 adapter。
- 成功：只有 D1 完整批次完成才显示成功。

## 响应式与无障碍

桌面使用紧凑资源表，640px 以下切换异常优先卡片；390px 单列无横向滚动。按钮有键盘焦点、禁用原因和文字状态，颜色不是唯一状态载体，符合 WCAG AA。钉钉 WebView 只查看状态；需要操作时明确去公司 Mac。

## 视觉验收

在 1440、1180、640、390px 检查：全成功、部分成功、设备离线、等待登录、等待验证码、字段变化、官方无记录、无权限；同时确认巨量千川没有混入抖店自然经营事实。
