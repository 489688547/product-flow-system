# 抖店罗盘经营数据采集设计

## 设计状态

- 状态：专用浏览器重构已确认，待实施
- 最近更新：2026-07-25
- 架构决策：`docs/decisions/2026-07-25-dedicated-browser-collection.md`

## 用户任务

数据负责人需要确认抖店昨天四类经营数据是否完整入库，并在失败时知道由谁、在哪台设备、哪个
Chrome Profile 执行什么恢复动作。老板和运营只消费数据库事实，不进入抖店逐项抄数。

现有 MV3 扩展可以完成真实采集，但长任务会受到 Service Worker 生命周期、本地扩展目录和内容脚本
重载影响。重构后由公司 Mac 后台服务管理持久化专用 Chrome Profile；Chrome 只承担登录页面内的
短操作，本机服务承担耗时的数据处理和恢复。

## 总体架构

```text
云端任务控制面
  -> 公司 Mac 采集监管服务
    -> 抖店专用 Chrome Profile
      -> 固定页面操作 / 官方下载 / 白名单指标
    -> 本机等待、归档、解析、校验、断点恢复
  -> 受控标准事实 ingest API
  -> 服务端选择的业务 D1
```

- 控制面继续拥有任务、租约、目标环境、版本、运行记录、游标和告警。
- 本机采集服务拥有 Profile 目录、浏览器进程、任务检查点、原始文件和本地诊断。
- Chrome 不持有 D1、Pages 或 runner 凭据；浏览器页面只能返回固定结果给本机采集服务。
- Pages Functions 是唯一 D1 写入边界；本机不能选择 binding、数据库 ID 或展示版本。
- 能力评审结论为“扩展现有能力”，不创建第二套任务或同步记录系统。

## Chrome 与本机职责

### Chrome 的短操作

- 打开代码登记的抖店或罗盘页面。
- 判断登录、验证码、扫码、滑块或设备验证状态。
- 读取顶部店铺名称和稳定店铺 ID，防止串店。
- 选择服务端任务指定的业务日期。
- 点击官方报表导出并把下载事件交给本机服务。
- 官方没有报表时，只读取 adapter 白名单中的固定指标名称和数值。

### 本机的耗时操作

- 启动、监管、重启专用 Chrome 和持久 Profile。
- 等待报表生成和下载完成，检查文件稳定性。
- 哈希归档原始文件、解析大文件、执行字段和业务日校验。
- 分块上传、幂等提交、断点恢复和安全重试。
- 保存本地加密失败截图与脱敏页面结构指纹，7 天后自动删除。
- 上报设备、阶段、成功、失败、等待人工和页面变化。

Chrome 不解析文件、不决定业务口径、不保存批次、不直接写 D1。

## 信息层级

- 主信息：昨天四类资源是否就绪、数据截止日、覆盖率、行数、最后可信日期。
- 辅助信息：店铺、任务阶段、完成时间、来源版本、错误和恢复动作。
- 低频信息：attempt、adapter/schema version、文件哈希、Profile、历史运行和本地诊断编号。
- 永不展示：凭据、Cookie、Token、验证码、完整页面、原始文件、绝对路径、本地截图和客户个人信息。

## 页面结构

- 不新增导航。
- “数据接入 → 电商平台”删除重复的全局摘要/刷新块。抖音卡片只显示平台、已登记店铺名称、店铺 ID 和“添加”；adapter readiness、资源进度和恢复动作只在“数据同步”呈现。
- “数据同步”复用现有设备、异常优先、执行记录和恢复动作，增加四个抖店资源和 Profile 状态。
- 业务 App 通过 `/api/platform/v1/commerce-facts` 查询事实，不直接调用插件或抖店。
- 巨量千川保持独立的未接入广告平台卡片。

## 交互流程

### 日常成功

数据负责人可先用“添加”登记店铺名称和店铺 ID；重复 ID 幂等更新名称。首次运行时，专用 Chrome
在固定店铺管理页识别稳定店铺 ID 和店铺名，服务端核对目录后生成四个任务；公司 Mac 依次领取、
下载或安全读取、归档、解析、提交。页面逐资源显示完成时间、行数、覆盖率、可信等级和最新日期。

### 多店铺与登录隔离

不同账号分别使用独立持久 Chrome Profile，不使用默认个人 Profile 或无痕标签隔离 Cookie。同一账号
可切换的多个店铺可以共用 Profile，但每次执行前都读取并核对当前店铺 ID。控制面只返回该
Profile 已登记店铺的抖音任务；不匹配时停止采集并进入人工恢复。

Profile 由本机采集监管服务启动并管理。后台服务重启后复用相同 `user-data-dir`；Chrome 保持可见，
员工只在登录、验证码、扫码或店铺切换时介入。

### 部分就绪

四类资源独立呈现。商品成功但直播失败时整体为“部分就绪”，业务 App 不补齐失败资源；上一可信直播批次仍可读，并明确当前请求日期状态。

### 人工恢复

任务进入 `waiting_human` 后显示“打开专用抖店浏览器”。员工在公司 Mac 指定 Profile 完成登录或
验证，再点击“我已处理，重新采集”；系统从最后安全检查点恢复原店铺、资源和业务日，不创建自由
URL、脚本或 selector。

## 组件复用

- 复用现有 runner 身份、任务租约、游标、通知、严格任务投影和标准事实 ingest。
- 新增浏览器监管、Profile 注册、执行检查点和 Provider 页面执行接口。
- 店铺自动发现只提交固定 `providerId/storeId/storeName`，服务端持有店铺目录。
- 店铺手工登记复用同一服务端目录和校验函数，由已授权会话执行；浏览器不得直接写 D1。
- 复用网页采集控制面的 job/run/cursor/runner/notification；不新建并行任务表。
- 复用数据同步页的状态徽标、执行记录、异常优先和设备卡片。
- 复用业务数据库选择中间件、流式 XLSX/CSV 解析和显示数据目录。
- 抖店 adapter 先迁移到专用浏览器；稳定后将快麦迁移到相同 executor/processor 接口。

## 页面状态

- 加载：读取 runner、专用浏览器、Profile、四资源任务、游标和质量。
- 尚未运行：明确“尚未到今日计划时间”或“尚未完成真实验收”。
- 官方无记录：显示 0 行且高可信，不显示错误。
- 设备离线：给出公司 Mac 和启动后台服务动作。
- 浏览器离线：给出指定 Profile 和“打开专用浏览器”动作。
- 未登录/人工验证：显示同一 Profile 的恢复动作。
- 页面变化：显示“等待适配”，停止对应资源写入，并给出本地诊断编号。
- 无权限：可查看安全摘要，不能重试或启停 adapter。
- 成功：只有 D1 完整批次完成才显示成功。

## 响应式与无障碍

桌面使用紧凑资源表，640px 以下切换异常优先卡片；390px 单列无横向滚动。按钮有键盘焦点、禁用原因和文字状态，颜色不是唯一状态载体，符合 WCAG AA。钉钉 WebView 只查看状态；需要操作时明确去公司 Mac。

## 视觉验收

在 1440、1180、640、390px 检查：全成功、部分成功、设备离线、浏览器离线、等待登录、等待验证码、
字段变化、官方无记录、无权限；同时确认巨量千川没有混入抖店自然经营事实。

## 超时、重试与检查点

- 页面短操作使用独立超时，不允许在 Chrome 上等待长时间文件处理。
- 网络、报表生成慢和下载超时最多自动重试 3 次；人工验证不消耗重试次数。
- `profile_ready`、`page_ready`、`export_requested`、`download_stable`、`validated`、`ingested`
  是可恢复检查点。
- 服务或 Chrome 重启后从最后安全检查点恢复；过期任务进入终态并生成新重试，不永久显示运行中。
- 07:30 前仍未成功时生成数据同步待处理事项，明确平台、Profile、店铺、资源、设备和恢复条件。

## 迁移验收

1. 使用 2026-07-23 已成功的四资源批次作为解析和查询回归基准。
2. 新运行时完成最新业务日四资源真实采集，分别验证日期、行数、覆盖率和关键金额。
3. 插件与新运行时通过执行器版本和租约互斥，同一任务不能重复领取。
4. 专用浏览器连续成功运行 7 天后，MV3 扩展退出自动领取，仅保留短期回滚。
5. 抖店稳定后迁移快麦；巨量千川在独立口径和页面验收后接入。
