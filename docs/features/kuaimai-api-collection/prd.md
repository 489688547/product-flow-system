# 快麦订单接口采集 PRD

## 文档状态

- 状态：验证完成，待实现
- 负责人：数据中心
- 最近更新：2026-07-29

## 背景与问题

07-25 至 07-27 在系统中显示为断档或残缺，但实测快麦源头订单量完全正常
（6556 / 6625 / 6732 单）。**缺口来自采集管道，不是源头缺数据。**

现有管道依赖操作网页导出文件，故障集中在登录失效、人工验证、时间范围未生效、
导出确认缺失，合计占快麦侧失败的大部分。

## 目标

- 快麦订单改为直接调用其查询接口，按业务日取数
- 消除对网页导出流程的依赖
- 口径与 PRODUCT.md 一致：使用订单创建时间

## 非目标

- 不改变销售事实的存储结构与入库链路
- 不改变抖店侧采集
- 不接入快麦开放平台（当前状态为 integrating，未打通）

## 业务规则

- `timeType` 必须为 `created`（订单创建时间）。接口对无效值静默回落到付款时间，
  因此必须白名单校验，不得依赖接口报错
- 时间范围按 `Asia/Shanghai` 自然日的毫秒时间戳
- 分页拉取必须有明确的终止条件与总数校验

## 异常与边界

- 登录失效：接口返回非成功，需人工登录
- 拉取条数与 `data.total` 不一致：视为失败，不得入库部分数据
- `timeType` 不在白名单：直接拒绝，不发请求

## 验收标准

- 指定业务日拉取的订单数与 `/trade/search/count` 的 `data.total` 一致
- 使用 `created` 口径，与页面默认的 `pay_time` 结果不同且更大
- 07-25 至 07-27 三天的数据可完整补齐

## 上线与回滚

与现有网页导出管道并存，按资源灰度切换；异常时回退到导入官方报表。
