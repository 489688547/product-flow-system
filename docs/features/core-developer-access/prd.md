# 核心开发人员本地数据访问 PRD

## 文档状态

- 状态：已评审
- 负责人：总经办
- 最近更新：2026-08-07
- 关联事项：DEV-000014

## 背景与问题

核心开发人员 fork 仓库后，根目录缺少启动说明，本地启动又依赖未交付的个人
Token。空白 SQLite 只能验证启动，不能让前端开发基于完整公司数据工作。复制共享
Token 会丢失个人审计和单独撤销能力。

## 目标

- 每位获授权核心开发人员只接收一份个人 `developer.env`。
- 文件固定放到 `~/.config/product-flow-system/developer.env` 后，任意 fork/worktree 的
  `npm start` 自动使用本地前端和生产 API。
- 开发人员获得生产业务数据读写权限，所有请求绑定其钉钉稳定身份。
- 没有该文件时，`npm start` 保持零 Secret 本地 SQLite 沙箱。

## 非目标

- 不共享 Token，不把 Token 写进仓库、浏览器、URL、日志或 PR。
- 不向开发文件下发钉钉、快麦、灵算等平台 Secret、Cookie 或数据库文件。
- 不允许 fork、GitHub 身份或仅知道姓名的人自动签发生产权限。
- 不取消生产写入快照、版本冲突和审计规则。
- 不让尚未部署的本地 Functions 代码直接读写生产库；后端改动仍在沙箱和固定测试环境
  验证。

## 用户与权限

- 总经办：确认人员、签发、撤销和重新签发个人开发文件。
- 核心开发人员：持个人文件时具有生产业务数据 `read`、`write` 和
  `core_developer` 能力；服务端仍要求钉钉组织成员处于 active。
- 普通开发人员：没有文件时只使用本地沙箱。
- 平台 Secret 的 reveal/grant 权限保持现有独立规则，不随数据权限自动开放。

## 当前流程

成员 fork 后运行 `npm start`，因缺少共享 `.env` 被阻断；即使手工建立空文件，也只
能进入无真实数据的本地沙箱。生产 Token 没有签发工具，只能人工操作数据库。

## 目标流程

1. 总经办确认核心开发人员的钉钉组织身份。
2. ECS 上的受控签发脚本生成随机个人 Token，只保存 SHA-256 哈希，并输出权限文件。
3. 总经办把每人的文件单独交付；成员固定放到用户配置目录。
4. `npm start` 检测到有效文件后，只启动本地 Vite，并由服务端代理向生产 API 注入
   个人 Token；浏览器永远看不到 Token。
5. 文件缺失、权限过期或撤销时，启动器明确报错或回到显式沙箱入口，不伪造身份。

## 业务规则

- 一人一 Token；文件不可共用。
- Token 必须绑定 `userId + unionId`，组织成员停用或身份不匹配立即失效。
- `core_developer` 是显式 Token 能力，不由姓名、部门或钉钉管理员标签自动推断。
- 本地代理只接受 `127.0.0.1:8127` 同源请求，并删除外部 Origin 后再访问生产 API。
- 本地页面持续显示“核心开发模式 · 生产真实数据”；禁止把该模式伪装成沙箱。
- Token 明文只出现于签发输出文件；命令输出仅显示路径、人员和安全指纹。

## 数据定义

复用 `production_data_access_tokens`：`token_hash`、稳定身份、姓名快照、
`capabilities`、创建/过期/撤销/最后使用时间。能力为 `read`、`write`、
`core_developer`。签发/撤销写入无秘密审计，不新增业务数据表。

## 异常与边界

- 同名或组织身份不唯一：拒绝签发。
- 文件权限不是 `0600`、缺字段或 URL 非正式 HTTPS Origin：启动失败并给出修复路径。
- Token 失效：API 返回稳定错误，前端不得回退共享身份或生产 Cookie。
- 正式 API 不可用：本地核心开发模式明确失败；开发人员可显式运行
  `npm run start:sandbox` 继续无生产数据开发。
- 核心模式验证本地前端对已部署生产 API 的行为；本地后端代码只有部署到固定测试
  环境后才会被该模式调用。

## 验收标准

- 两份不同 Token 的文件分别绑定各自身份，任一撤销不影响另一人。
- 文件放到固定目录后，fork 内只需安装依赖、构建并运行 `npm start`。
- `/api/auth/session` 返回对应个人身份和 `local-online-account` 登录模式。
- 浏览器源代码、Network 请求头、日志和 Git 状态均不出现 Token。
- GET 使用 read，写请求使用 write；无 `core_developer` 能力的非 executive Token
  继续被拒绝。
- 无文件时零 Secret 沙箱仍可启动。

## 上线与回滚

先合并到 `dev`，通过固定测试站和 ECS 测试 API，再由 `dev → main` 发布。上线后在
ECS 备份控制库，分别签发两份文件并验证身份。回滚时撤销两枚 Token、回退本地代理
与中间件；既有 executive Token 和生产业务数据不变。
