# 供应链共享平台 API 产品需求

## 背景

供应链管理 App 已按 13 个用户故事完成消费层设计，但除快麦当前库存快照外，库存历史与质量、销售日需求、采购付款、供应商、质量售后、统一采集任务和版本化供应链工作流尚无完整共享 API。页面不得以 legacy whole-state、浏览器缓存或硬编码样例替代这些事实。

本功能由数据中心与平台层负责，为供应链、数据中心、经营驾驶舱和公司 AI 提供同一组可复用事实与工作流契约。供应链 feature 只消费 API，不复制 D1 事实或另建第二套工作流。

## 用户故事映射

1. 库存监控与预警：库存 current/history/filter/quality，销售日需求，覆盖率与新鲜度。
2. 采购下单与跟进：采购建议、计划、批次及里程碑版本。
3. 供应商管理：只读供应商事实与版本化商务档案、能力、报价、评价、整改；秘密只保存保险箱引用。
4. 价格与成本：库存单位成本、供应商报价、BOM 和业务规则版本。
5. 跨部门协作：服务端责任范围、不可变事件、人工恢复状态。
6. 仓库与库存：库存快照、盘点、清仓建议。
7. 质量标准：标准文档与结构化规则双形态、版本和生效日期。
8. 质检执行：质检计划、记录和批次证据。
9. 质量问题闭环：发现、定性、处理、整改、验证、关闭六步事件。
10. 供应商质量评价：质量事件和供应商档案的稳定关联。
11. 应收应付：采购与付款独立事实和稳定关联。
12. 清仓建议：版本化建议、调整理由和运营确认。
13. 快递费核对：费率规则、核对单、财务确认和争议事件。

## 目标

- 补齐 `/api/platform/v1/goods-flow` 的库存 current/history/filter/quality 以及供应商、采购、付款、质量问题和售后只读事实。
- 新增 `/api/platform/v1/data-services/sales/daily`，固定订单创建时间、上海时区、排除“其它”的日级需求契约。
- 新增 `/api/platform/v1/data-tasks`，聚合网页采集与 ERP 批次的安全状态。
- 新增 `/api/platform/v1/supply-chain-workflows`，提供 16 类供应链实体的列表、创建和版本化动作。
- 所有写操作具备服务端权限、幂等、乐观版本、审计、稳定错误和展示数据策略。

## 非目标

- 不恢复快麦开放平台 API；快麦当前仍是 Chrome 官方文件采集来源。
- 不把客户、订单、原始售后内容、Cookie、Token 或凭据写入共享 API。
- 不在供应链 feature 中新增 D1 表或外部平台适配器。
- 不在本次直接调用钉钉审批或 ERP 写接口；外部动作保留明确的人工恢复状态。
- 不把 planned/integrating 平台标记为 connected。

## 数据定义

### 库存

- `current` 是不晚于 `asOf` 的最新完整快照日期的全部行，不按 SKU 各自取不同日期。
- `history` 返回历史快照行，可按 SKU、仓库和游标过滤。
- `date` 是快照采集日期；`sourceUpdatedAt` 是 ERP 行级更新时间。
- 未有真实商品稳定 ID 时 `productId=null`，不得由仓库与 SKU 伪造。
- 质量包含状态、新鲜度、覆盖率、可信度和缺失项。

### 销售需求

- 时间口径固定 `create_time`，时区 `Asia/Shanghai`，排除空平台、其它、其他、未知和未知平台。
- 粒度固定 `date × inventoryUnitId × platform`。
- `grossQuantity` 来自销售数量；退款只有金额事实时，不伪造退货件数，`returnQuantity` 和 `netQuantity` 为 `null` 并在质量缺失项声明。
- 促销活动没有来源事实时 `promotionIds=[]`，同时声明 `promotionIds` 未覆盖。

### 采购、付款、供应商、质量和售后

- 采购与付款是独立集合，以稳定采购 ID 关联。
- 只读事实优先来自货流事件；供应商和质量问题暂从现有服务端 whole-state 读取并安全投影，响应必须披露来源和部分覆盖。
- 售后只返回已标准化事实；来源未接入时返回空集合和 `unavailable/partial`，不返回伪造样例。

### 工作流

- 所有实体有稳定 `resource + id`、`status`、`version`、服务端责任部门和不可变事件。
- 新建生成版本 1；每个动作成功后版本加一。
- 客户端不能提交操作者、责任部门或审计字段。
- 归档替代物理删除。
- 敏感信息仅允许保存 `credentialVaultEntryId` 等保险箱引用。

## 权限

- 有效钉钉会话是所有路由的前提。
- executive 可读取全部事实和金额、维护全部工作流。
- 供应链/采购维护采购、供应商、BOM、业务规则、清仓；质量维护质量标准、质检与质量问题；财务维护采购付款关联、费率和运费核对；仓库维护质检执行和库存相关动作；产品维护 BOM 与质量标准。
- 服务端使用会话身份和部门集合授权；前端隐藏按钮不构成授权。
- 只读身份不能执行任何写动作。

## 验收标准

- 供应链消费客户端无需 shape 兼容分支即可读取所有新接口。
- 当前库存查询只返回最新完整快照；历史、过滤、游标和质量状态有契约测试。
- 销售日事实携带固定 contract，缺失退款件数和促销事实时不补零。
- 只读事实 API 无数据时返回真实覆盖状态，不返回 404 或假数据。
- 工作流覆盖创建、幂等重放、版本冲突、部门拒绝、非法动作、敏感字段拒绝、归档和审计。
- 新表登记展示策略、环境能力、迁移与回滚；Pages Functions 构建通过。
- 合并到 `main` 后由 Cloudflare Git 部署，并完成生产 readiness 与受权 executive 读取验收。
