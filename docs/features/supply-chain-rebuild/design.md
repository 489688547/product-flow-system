# 供应链管理重做功能设计书

## 用户任务

供应链用户进入 App 后首先判断“今天要处理什么、哪一批会晚、缺什么数据”，随后完成建议复核、采购发起、跟进、质检、收货、付款或问题关闭。产品经理从产品视角查看货流进度，主管与总经办从风险和资金视角查看全局。

## 信息层级

1. 主信息：我的待处理、逾期风险、当前货流节点、责任人、下一步操作。
2. 辅助信息：库存、销量、备货周期、预计到货、成本和数据新鲜度。
3. 低频信息：完整历史、规则版本、来源批次、同步记录和审计。

数据解释使用“指标名称 + 小信息图标”。表格筛选和排序统一使用“列名 + 轻量图标按钮”，不在表头放胶囊筛选器。

## 页面结构

左侧导航固定为：

1. 我的工作台
2. 计划与采购
3. 供应商
4. 生产与在途
5. 库存与盘点
6. 质量闭环
7. 成本与财务
8. 数据与规则

### 我的工作台

- 顶部为角色范围、数据截止时间和刷新入口。
- 第一层为待处理、即将逾期、数据问题三个计数入口，不用装饰性 KPI 卡。
- 第二层为按优先级排列的任务列表，展示对象、原因、责任、截止时间和主动作。
- 第三层为产品货流摘要，显示各产品风险批次和预计补货状态。

### 计划与采购

- 视图切换：库存预警、采购建议、采购申请、采购订单、清仓建议。
- 建议详情采用“系统依据—人工调整—确认影响”三栏。
- 采购批次详情内嵌货流进度和付款关联，不把审批、订单与节点拆散到多个弹窗。

### 供应商

- 列表默认展示供应商简称、能力、主要品类、等级、准时率、合格率、采购占比和风险。
- 详情分为选择决策、合作事务、价格与报价、产品表现、问题整改和评价历史。
- 银行、证件等敏感信息只显示掩码与受控查看入口。

### 生产与在途

- 产品汇总显示每个产品的批次数、当前最慢节点、风险和预计可售天数。
- 下钻后按批次显示“快递式”进度线：
  `采购申请 → 审批 → 下单 → 生产/备货 → 发运 → 到仓 → 质检 → 入库 → 结案`。
- 当前节点使用一次性前进动效；逾期节点展示原因与责任人；减少动效时静态展示。

### 库存与盘点

- 视图切换：当前库存、库存历史、盘点任务、物料/BOM、异常与清仓。
- 表格按仓库和 SKU 展示数量、可售天数、更新时间、覆盖和可信状态。
- 盘点流程分为提交实盘、确认数量差异、财务确认金额、关闭。

### 质量闭环

- 视图切换：质量标准、检查计划、质检记录、质量问题、供应商质量评价。
- 标准详情并排展示完整知识库与精简检查清单。
- 质检默认显示应检未检、已检合格、已检不合格三组。
- 问题详情使用发现、定性、处理、整改、验证、关闭进度。

### 成本与财务

- 视图切换：价格历史与比价、BOM 成本、应收应付、快递费核对、现金循环。
- 金额默认右对齐并显示口径信息图标。
- 应收应付必须从汇总下钻到采购单、付款单和批次。

### 数据与规则

- 只展示与供应链有关的数据覆盖、责任规则、阈值、BOM 版本和业务规则。
- 采集任务跳转到数据中心统一“数据同步”，不复制调度器。
- 快麦、ERP、抖音等接入状态遵循集成注册表；`integrating` 不显示“已接通”。

## 交互流程

### 采购建议

1. 用户从待处理或库存预警进入建议详情。
2. 系统展示库存、销售、同比、活动、周期、MOQ 与产能的覆盖情况。
3. 用户调整数量时填写原因，页面同步预览采购后可售天数和资金占用。
4. 主管确认后生成采购计划版本；提交钉钉审批前二次确认。
5. 外部动作失败时保留计划并生成带恢复说明的待办。

### 货流进度

1. 产品经理选择产品，查看所有活跃批次摘要。
2. 选择批次后，焦点移动到批次详情标题。
3. 每个节点展示计划、实际、责任、证据与异常。
4. 点击异常进入对应操作，不允许直接在进度线上伪造完成。

### 质量问题

1. 从质检、售后、客户反馈或人工发起问题。
2. 质量主管确认严重度和定性；建议可修改但必须留理由。
3. 系统按定性生成处置事项并通知责任人。
4. 整改完成后绑定下一批验证；验证通过方可关闭。

## 组件复用

- `PageHeader`：页面标题和少量全局动作。
- `Button`：主次、危险和禁用状态。
- `DataTable`：业务表格与横向滚动。
- 现有状态徽标、弹窗和本地线上环境提示继续复用。
- 公司协同中心用于跨部门事项，不在供应链新建通用待办组件。

## 新增组件

### `SupplyChainWorkbench`

- 职责：按角色聚合待办、逾期与数据问题。
- 输入：任务、权限范围、覆盖状态和动作回调。
- 状态：加载、空、部分覆盖、错误、无权限。
- 键盘：列表按文档顺序导航，主动作使用原生按钮。

### `GoodsFlowProgress`

- 职责：展示产品或批次的连续货流节点。
- 输入：节点、当前状态、计划/实际时间、责任和异常。
- 输出：选择节点事件，不直接修改业务状态。
- 动效：节点完成时一次性推进 240—360ms；支持 `prefers-reduced-motion`。
- 复用边界：只用于有明确顺序与证据的业务流程，不用于普通状态列表。

### `CoverageNotice`

- 职责：统一展示可信、部分、过期、不可用。
- 输入：状态、最后成功时间、覆盖率、缺失项和恢复动作。
- 颜色外同时使用图标和文本。

### `MetricDefinitionHint`

- 职责：以小图标展示定义、公式、时间口径、来源和版本。
- 悬停、点击和键盘聚焦均可打开；Escape 关闭。

## 页面状态

- 加载：先展示页面骨架，局部 API 独立加载，避免整页阻塞。
- 空数据：说明是没有业务记录还是数据尚未接入，并提供正确下一步。
- 错误：保留上次可信数据，标出受影响模块、请求编号和重试。
- 无权限：说明当前范围与责任来源，不展示敏感数据。
- 禁用：按钮显示禁用原因，例如“库存覆盖不足，不能生成采购建议”。
- 成功：反馈对象、版本和下一节点，不只显示“保存成功”。
- 过期：展示最后成功时间，并阻止需要实时数据的确认动作。
- 部分覆盖：只计算覆盖范围，明确未覆盖仓库、SKU 或日期。
- 版本冲突：展示最新操作者和更新时间，要求刷新后重做修改。

## 响应式与钉钉 WebView

- 1440px 与 1180px 保留左侧导航和主表可读宽度。
- 窄 WebView 折叠导航，顶部保留当前工作区和返回菜单。
- 表格列不逐字折行，列宽不足时横向滚动。
- 货流进度在窄屏改为纵向时间线，节点信息不横向挤压。
- 弹窗在手机宽度占满可用视口并适配安全区、动态视口高度。

## 交互文案

- 数据缺失：“当前没有足够数据计算，不按 0 处理。”
- 数据过期：“库存最近成功更新于 {time}，确认采购前请先恢复数据。”
- 采购建议禁用：“销售或库存覆盖不足，暂不能生成可靠建议。”
- 外部失败：“采购计划已保存；钉钉审批未发起，请按恢复步骤重试。”
- 进度等待：“等待来源数据，不推断已完成。”
- 质量未检：“应检未检，不等于检验合格。”

## 无障碍

- 所有筛选、排序、说明和进度节点可用键盘操作并有可见焦点。
- 图标按钮必须有完整 `aria-label`，当前筛选值进入辅助名称。
- 状态不只依赖颜色；金额、时间和数量使用可读文本。
- 弹窗打开后管理焦点，关闭后回到触发按钮。
- 动效遵循 `prefers-reduced-motion`，不使用循环闪烁。
- 正文、次要文字和状态满足 WCAG AA 对比度。

## 视觉验收

- 1440px：8 个工作区导航、我的工作台、计划与采购、供应商、横向货流进度。
- 1180px：主表、筛选菜单、采购建议详情。
- 390px：折叠导航、纵向货流进度、全屏详情、底部操作。
- 状态：无数据、部分覆盖、过期、错误、无权限、禁用、版本冲突、减少动效。
