# 供应链管理重做 PRD

## 文档状态

- 状态：开发中
- 业务负责人：供应链、质量、财务与总经办
- 研发待办：`DEV-000004`
- 数据依赖：`DEV-000005`（共享只读事实）、`DEV-000006`（版本化供应链工作流命令）
- 最近更新：2026-07-25

## 背景与问题

现有供应链 App 已具备货流 Phase 0、库存盘点、钉钉采购与付款审批、供应商档案和质量导入等局部能力，但导航以系统对象划分，多个页面仍是阶段占位。采购专员无法从“今天要处理什么”进入业务，产品经理也无法看到一批货从申请、生产、发运到入库的连续进度。

本次以《企业管理系统 · 采购供应链与质量模块 用户故事梳理》为完整范围，覆盖采购线 9 个场景和质量线 4 个场景。商品、库存、销售、采集任务等事实必须由数据中心共享 API 提供；供应链 App 负责采购、供应商、生产跟进、盘点、质量和财务协同语义，不复制事实源。

## 目标

1. 角色进入 App 后首先看到自己需要处理、即将逾期和数据不完整的事项。
2. 将库存异常、采购建议、采购申请、付款、生产、物流、质检、入库和结案串成可追溯闭环。
3. 产品经理可按产品查看汇总货流进度，并下钻到每个采购批次的“快递式”时间线。
4. 供应商档案、价格历史、BOM、质量和履约表现形成同一业务关系，不重复维护商品事实。
5. 13 个场景均有对应页面、责任角色、数据来源、异常状态和验收测试。
6. 缺失、过期、部分覆盖的数据明确显示为未知或待补齐，不以零代替。

## 非目标

- 不替代快麦 ERP 的库存扣减、发货、WMS、采购单和收货能力。
- 不在供应链模块建立第二套商品目录、销售事实、库存事实或采集任务控制面。
- 不在本期直接依赖仍为 `planned` 的巨量引擎或千川数据。
- 不自动替代主管、采购、质量或财务的最终业务判断。
- 不保存供应商身份证、银行卡图片或外部系统原始敏感响应到普通业务表。

## 用户与权限

| 角色 | 默认范围 | 可执行动作 |
| --- | --- | --- |
| 品牌采购专员 | 自己负责的品类、供应商、物料、SKU | 调整建议、发起采购、跟进交期、提交清仓和运费异常 |
| 品牌采购主管 | 品牌采购全部范围 | 指派责任、确认计划、处理冲突、查看团队与经营汇总 |
| 生产采购专员 | 所属工厂的原料、耗材和生产采购 | 维护原料计划、跟进到厂、反馈产能 |
| 生产采购主管 / 厂长 | 所属工厂全部生产采购 | 确认生产计划、产能、批次和异常 |
| 仓库 | 所属仓库与待收货批次 | 实盘、收货数量确认、入库与盘点提交 |
| 质量 | 质量标准、检查计划、质检记录和问题闭环 | 维护标准、执行/安排质检、定性、整改验证 |
| 财务 | 采购付款、应收应付、成本和运费核对 | 确认付款、金额差异、月度资产与费用 |
| 产品经理 | 负责产品的质量标准和货流进度 | 查看货流、确认质量标准更新、参与缺陷决策 |
| 运营 | 活动与清仓协同 | 登记活动、接收清仓建议、查看影响 |
| 总经办 | 全部 | 查看、分配、确认和审计 |

同一账号可拥有多个岗位。权限必须由服务端依据组织身份和责任范围校验，前端隐藏操作不是授权。

## 当前流程

1. 库存、销售、生产周期和活动信息分散在 ERP、钉钉文档和人工表格。
2. 采购建议依赖人工核对，调整原因与结果缺少结构化回流。
3. 采购与付款虽可从钉钉同步，但跟生产、物流、质检和收货没有统一进度。
4. 供应商档案、报价、质量问题和评价分散，难以按产品或供应商追溯。
5. 质量标准与质检记录未形成“发现—定性—整改—验证—关闭”的连续状态。

## 目标流程

1. 数据中心提供商品、库存、销售、采购付款投影、质量售后和同步覆盖。
2. 系统按责任配置生成异常、采购建议和协同任务。
3. 采购专员检查依据、调整数量并记录理由，主管确认后发起钉钉采购申请。
4. 审批通过后关联 ERP 采购单；不能自动执行时生成带系统入口和操作说明的人工待办。
5. 批次依次记录排产、产完、发运、到仓、质检、收货和结案；超期节点通知责任人。
6. 付款申请与采购申请保持独立实体，并以采购单号或审批实例稳定关联。
7. 质量不合格自动进入问题闭环，整改完成后在下一批触发验证。
8. 业务完成后的调整、评价和客观结果回写规则版本，保留操作者与审计。

## 业务规则

### 共同规则

- 商品身份使用共享 `productId` 与 `sku.id`；69 码和内部唯一编码均可作为业务编码，不用长度猜测身份。
- 订单与销售需求按订单创建时间、`Asia/Shanghai` 统计，默认排除“其它”平台。
- 建议类结果必须人工确认后生效；纯统计事实可直接展示。
- 每条判断显示来源、统计截止时间、覆盖率、可信等级和计算规则版本。
- 同一业务动作必须具备幂等键、乐观版本和审计记录。
- 采购、付款、质检、收货、整改均保留独立状态，不以一个“完成”覆盖真实过程。

### 货流进度

- 产品级进度汇总按负责产品展示当前覆盖批次数、最晚节点、风险批次和预计可售天数。
- 批次级进度固定为：采购申请、审批通过、采购下单、生产/备货、发运、到仓、质检、收货入库、结案。
- 未涉及的节点显示“不适用”；没有事实的节点显示“等待数据”，不能推断完成。
- 动效只表达当前节点流转，不持续闪烁；用户设置减少动效时完全静态。

### 采购建议

- 最低覆盖一个最长备货周期。
- 结合往年同期销售、运营活动和常规 15—30 天需求；阈值均为可版本化规则。
- 共用物料按所有相关 BOM 聚合，并应用起订量与供应商产能上限。
- 人工调整必须填写原因；建议值、调整值、最终值和结果分别保存。

### 库存与成本

- 当前库存由数据中心库存 API 提供，前端不得从历史数组自行挑选“最新一条”。
- 理论库存与实盘差异默认 5% 内可接受，规则可配置；超阈值必须确认原因。
- 成本依据 BOM 的组成 SKU 单位成本乘用量汇总，再应用可配置损耗比例；缺少任一成本时结果为不完整。

### 质量

- 每个产品同时保留完整标准与精简检查清单，并独立版本化。
- 首批检查和后续抽检使用同一检查项版本，记录触发类型。
- 质量记录状态为应检未检、已检合格、已检不合格。
- 问题状态为发现、定性、处理、整改、验证、关闭；关闭前必须有验证结果或获授权的例外说明。

## 数据定义

| 对象 | 关键身份 | 来源 | 供应链职责 |
| --- | --- | --- | --- |
| 商品 / SKU / 组合关系 | `productId`、`sku.id` | 产品目录 API | 只读消费与业务关联 |
| 库存事实 | 日期 + `skuId` + `warehouseId` | goods-flow inventory | 预警、盘点和计划输入 |
| 销售需求 | 日期 + 库存单位 + 平台 | sales daily | 需求、清仓和爆单输入 |
| 供应商 | `supplierId` | goods-flow supplier read model + 供应链维护 | 能力、商务与评价 |
| 采购 | `purchaseId` / 钉钉实例 ID | 钉钉、ERP、供应链工作流 | 计划、责任、状态与节点 |
| 付款 | `paymentId` / 钉钉实例 ID | 钉钉、财务确认 | 与采购独立关联 |
| 质量事件 | `incidentId` | 质检、售后、评价、人工 | 定性、处置、验证 |
| 数据任务 | `jobId/runId/batchId/archiveId` | data-tasks | 新鲜度、错误与恢复 |

快麦、ERP 文件和抖音当前为 `integrating`。页面依据 `coverage`、`lastSuccessfulSyncAt` 和可信状态展示可用范围，不将规划数据写成已接通。

## 异常与边界

- 数据源不可用：保留上次可信结果，标注受影响范围、最后成功时间和恢复入口。
- 数据部分覆盖：只对覆盖范围计算，汇总不外推。
- 编码未映射：作为数据质量问题，不猜测商品归属。
- 重复提交：按幂等键返回原结果。
- 版本冲突：阻止覆盖，提示刷新并展示他人最近修改。
- 无责任人或责任交叉：进入主管待分配，不自动随机指派。
- 审批或 ERP 自动操作失败：保留业务草稿并生成明确人工待办。
- 供应商敏感字段：列表与普通详情只返回掩码；显式授权查看需单独受控流程。
- 组合物料缺成本、BOM 或产能：建议与成本标为不完整，禁止生成伪精确值。

## 验收标准

1. 8 个工作区在左侧导航中按确认顺序展示，旧入口可重定向到对应新入口。
2. 不同角色进入“我的工作台”时，只看到自己有权处理的事项；主管可切换全部和按人筛选。
3. 产品级货流汇总与批次时间线能区分完成、当前、逾期、等待数据和不适用。
4. 采购建议展示计算依据，人工修改要求原因，确认后形成可追溯版本。
5. 采购与付款各自拥有状态和审批 ID，并能从付款回到对应采购。
6. 供应商可按能力筛选，并展示价格、履约、质量、集中度和单一来源风险。
7. 库存页支持多仓当前快照、历史、盘点差异和质量状态；过期数据不作为正常库存。
8. 质量标准、质检计划、质检记录和问题闭环可完整下钻，未检与合格明确区分。
9. 应收应付、成本、快递费和清仓建议均能追溯到源采购、SKU 或费用明细。
10. 所有 13 个场景在 `tasks.md` 中有测试映射，不能以占位页标记完成。
11. 加载、空、错误、无权限、过期、部分覆盖、版本冲突和外部失败均有独立状态。
12. 笔记本、窄屏和钉钉 WebView 可用，键盘焦点与减少动效通过验收。

## 上线与回滚

- 使用现有供应链 App 路由渐进替换，不建立第二个 App。
- 每阶段通过功能开关或兼容路由发布；未完成阶段继续使用已验证旧能力，不显示假数据。
- 共享只读 API 由 `DEV-000005` 按独立 PR 交付；版本化规则、建议、采购批次、质量和财务动作由 `DEV-000006` 在 `/api/platform/v1/supply-chain-workflows` 交付。供应链客户端在契约未就绪时显示明确缺口或禁用状态，不把 planned 能力展示成可写。
- 旧 `/api/supply-chain` 仅作为迁移兼容读取，不在新页面新增整状态覆盖写入。
- 生产交付仅通过 GitHub PR 合并 `main` 后由 Cloudflare Git 自动部署。
- 回滚前端版本不删除业务事实；版本化记录与审计不可回滚覆盖。
