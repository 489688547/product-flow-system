# 数据总览店铺经营数据设计书

## 用户任务

运营进入数据总览后，除了公司级统一 KPI，还要能按店铺快速查看抖店当日经营表现：整体成交、重点商品排名、直播/短视频贡献，并一眼判断相较昨天是升是降。

## 信息层级

1. 主信息：选中店铺的最新业务日、店铺每日 KPI 及同比昨天。
2. 辅助信息：重点商品 Top 10（含同比）、直播与短视频摘要。
3. 低频信息：无店铺、无数据、无权限、读取失败的空/错/降级提示。

该区位于总览既有「经营趋势 / 平台分布」栅格之下，作为独立 `section-panel`，不打断原有公司级 KPI 阅读顺序。

## 页面结构

- 区头左侧为标题与业务日说明，右侧为店铺切换下拉（`Store` 图标 + 原生 `select`，复用总览简洁风格）。
- KPI 采用自适应网格（`store-ops-kpi-grid`，`auto-fit`），每项主值下方一行同比徽标，复用总览既有 `data-kpi-comparison`（`favorable`/`unfavorable`/`neutral` 与上下箭头）。
- 下方两列：左为重点商品 Top 10（复用 `DataTable`），右为直播/短视频摘要（复用 `data-contribution-list`）。窄屏单列堆叠。

## 状态

- 加载中：显示旋转图标与文案，若已有旧业务日则保留旧数据。
- 无店铺：`尚无已登记的抖店店铺`。
- 店铺无数据：`该店铺暂无经营数据，等待抖店罗盘采集完成后显示`。
- 无权限（403）：`当前账号无权查看店铺经营数据`，不渲染数据，不影响总览其余部分。
- 读取失败：显示错误文案；快速切换店铺时用请求令牌丢弃过期结果，避免错位。

## 复用与边界

- 展示视图为纯函数（`src/domain/commerceOperationsView.js`），不含 React/网络。
- 取数编排为 `src/state/useStoreOperations.js`，仅在 overview 分区启用；店铺清单复用 `loadWebCollectionStatus`，经营事实走 `loadCommerceFacts`。
- 面板 `StoreOperationsPanel` 通过 props 接收数据，遵循总览既有 prop 传递方式，不直接调用外部系统。
