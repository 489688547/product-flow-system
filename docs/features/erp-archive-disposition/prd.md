# ERP 归档入库决策 PRD

## 文档状态

- 状态：开发中
- 负责人：数据采集
- 最近更新：2026-07-28
- 研发待办：DEV-000009

## 背景与问题

本机原始归档当前只有 `archived / processing / processed / failed` 运行状态。数据中心把所有
`archived` 都解释为“已下载未入库”，导致两类完全不同的记录混在同一个告警中：

- 已明确不纳入标准事实的历史文件，例如缺少订单创建时间或明细体量暂不复制到 D1。
- 已进入 `processing` 但执行进程消失、超过一天仍未完成的真实故障。

运行状态不能表达业务决策，文件名也不能作为决定是否入库的依据。

## 目标

- `processing` 超过 24 小时后自动转为可观察的失败，记录稳定错误码。
- 为归档增加服务端管理的入库决策，明确区分“待处理”和“有意跳过”。
- 数据同步页只对待处理、超时和失败记录告警；有意跳过记录折叠展示。
- 不删除原始文件、不覆盖已存在的可信事实、不按文件名猜测口径。

## 非目标

- 不把 1.37 GiB 历史订单商品明细逐行复制到 D1。
- 不修改销售事实口径、快麦页面适配器或公司 Mac 原始文件保留规则。
- 不自动推断 2026-07-22 历史文件的跳过原因。
- 不在本迁移中直接改生产业务记录。

## 用户与权限

- 总经办、数据中心/数据部、供应链和财务可记录或撤销归档入库决策。
- 其他已授权 ERP 归档查看者只能读取。
- 公司 Mac 采集器只上报运行状态，不能替用户设置“有意跳过”。
- 服务端验证权限、预期版本和受控原因码；隐藏按钮不是授权边界。

## 当前流程

1. 公司 Mac 下载并归档官方文件。
2. 线上保存安全归档索引。
3. `archived` 无法区分待处理与有意不入库。
4. `processing` 没有超时终态，进程消失后永久显示“处理中”。

## 目标流程

1. 归档继续按原流程保存运行状态。
2. 授权用户可对 `archived` 记录明确选择“不纳入标准事实”及原因。
3. 读取归档清单前，服务端把超过 24 小时的 `processing` 转为 `failed`。
4. 页面置顶显示待处理和失败；SLA 内处理显示中性；有意跳过记录折叠展示。
5. 需要重新采集时回到现有数据同步任务入口，不从归档文件名推断业务日期。

## 业务规则

- 运行状态保持 `archived / processing / processed / failed`，不新增伪运行状态 `skipped`。
- 入库决策独立保存为 `pending / skipped`。
- 仅 `archived` 可被标记为 `skipped`；`processing / failed / processed` 不允许用跳过掩盖。
- 跳过原因只允许：
  - `TIME_BASIS_MISSING`：缺少所需业务时间字段。
  - `DETAIL_STORAGE_DEFERRED`：原始明细已归档，标准事实已由其他受控投影提供，逐行索引延后。
  - `UNSUPPORTED_REPORT_GRAIN`：当前标准事实不支持该报表粒度。
- 撤销跳过会回到 `pending`，原因、操作人和操作时间清空并生成新版本。
- `processing` 从最后更新时间起超过 24 小时后转 `failed`，错误码固定为
  `ERP_COLLECTION_ARCHIVE_PROCESSING_TIMEOUT`。
- 超时转换不得修改 `batch_id`、`processed_at`、本地路径、文件哈希或业务事实。
- 所有决策写入要求 `expectedVersion`；同一版本重复提交返回版本冲突，不静默覆盖。

## 数据定义

- `ingestionDecision`：`pending | skipped`，旧记录默认 `pending`。
- `ingestionReasonCode`：受控原因码，仅 `skipped` 时存在。
- `decisionAt`、`decisionBy`：服务端记录的决定时间和组织身份。
- `version`：归档决策乐观锁版本，初始为 1。
- 超时依据：`updated_at`，缺失时回退 `archived_at`，统一使用 UTC ISO 时间比较。
- 展示环境策略：`erp_file_archives` 继续为 `skip`，不复制生产控制面归档索引。

## 异常与边界

- 旧库未迁移时新代码不得上线；部署顺序为迁移后应用。
- 未知原因码、非法状态、缺少版本、版本冲突分别返回稳定 4xx 错误。
- 读取时的超时自愈失败返回存储错误，不能继续用旧状态伪装成功。
- 处理中的记录在 24 小时内保持中性，不计入“卡住”告警。
- 历史回填只通过部署后的授权 PATCH 对已确认的精确归档 ID 执行，不写在迁移里。

## 验收标准

- 给定更新时间超过 24 小时的 `processing` 归档，GET 后为 `failed` 且错误码正确。
- 给定 24 小时内的 `processing` 归档，GET 后仍为 `processing`。
- 授权用户可把 `archived` 标记为受控 `skipped`；未授权、未知原因、旧版本均被拒绝。
- 跳过记录不出现在告警清单，折叠区显示原因；失败记录置顶显示。
- 页面和接口均不返回绝对路径、原始文件内容或凭据。
- 生产迁移后仅对报告已确认的 2026-07-22 精确记录执行回填并复核数量。

## 上线与回滚

先对 control D1 应用 `0017_erp_archive_disposition.sql`，再由 GitOps 发布应用。上线后通过正式
PATCH 回填已确认历史记录，不执行 SQL 猜测更新。若应用异常，回滚应用代码；新增列保持兼容。
若需撤销某条决策，使用正式 PATCH 回到 `pending`，不删除归档。超时失败可通过原有数据同步入口
重新采集，上一可信事实保持不变。
