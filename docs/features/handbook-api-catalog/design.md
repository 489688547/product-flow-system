# 说明书 API 目录功能设计书

## 用户任务

用户需要在一个页面内快速完成两层任务：

1. 先按 App 找到“现在有哪些 API、是否可用、谁能调用”。
2. 再进入单个接口，确认真实 Input、Output、错误码和当前只读调用结果。

目录优先帮助使用者判断“能不能用、怎么用”，不把所有文档正文平铺成一张超长页面。

平台能力评审结论为“扩展现有能力”：继续复用说明书的导航、Markdown 内容源、登录与权限边界，只为 API 分类增加机器目录和专用工作区，不创建第二套文档服务或 API 网关。

## 信息层级

### 主信息

- App、方法、路径、用途、状态。
- 认证与权限。
- Input、请求示例、Output、成功响应和错误码。
- 可实测 `GET` 的真实状态、耗时、`requestId` 和响应。

### 辅助信息

- 版本、调用方、兼容性和数据口径。
- 契约文件、契约测试和最后更新时间。
- 当前筛选和接口数量。

### 低频信息

- 废弃说明、迁移路径、可观测字段和重试限制。
- 响应截断、脱敏和实测安全规则说明。

## 页面结构

### 顶部分类

说明书顶部保留当前横向分类，并在“平台能力”后新增“API 目录”。分类切换继续使用说明书现有状态与深链机制。

### API 目录工作区

桌面端使用“筛选栏 + 接口列表 + 接口详情”的渐进下钻结构：

1. 顶部：关键词搜索、App、方法和状态筛选。
2. 左侧：匹配接口列表，显示方法、路径、名称、状态和权限摘要。
3. 右侧：当前接口完整契约。

没有选中接口时，默认选择当前筛选的第一项；筛选清空结果后不保留已经不匹配的详情。

接口详情固定按以下顺序：

1. 基础信息。
2. Input。
3. 请求示例。
4. Output。
5. 成功响应示例。
6. 错误码。
7. 契约来源。
8. 只读实测区，仅对登记过的 `GET` 出现。

### App 分组

筛选项使用稳定顺序：

- 全部
- 公司平台
- 产品全周期
- 供应链
- 数据中心
- 电商运营
- 品牌内容
- 人事绩效

接口只登记一次。跨 App 能力统一放“公司平台”，业务 App 通过“调用方”字段说明消费关系。

## 交互流程

### 查找接口

1. 用户进入“API 目录”。
2. 默认显示全部接口，并选中第一项。
3. 输入关键词时按名称、方法、路径、摘要和错误码本地过滤。
4. 切换 App、方法或状态后立即更新列表和结果数。
5. 点击接口列表项后，详情滚动到顶部并更新可复制深链。

### 查看与复制示例

1. 请求与响应使用格式化代码块展示。
2. 每个代码块有明确标题和“复制”按钮。
3. 复制成功显示短暂文本反馈，不使用仅靠颜色的提示。
4. 写接口示例上方固定显示“说明书不会执行写请求”。

### 测试只读接口

1. 只有 `liveTest.enabled=true` 且方法为 `GET` 时显示测试区域。
2. 页面根据登记表渲染允许的查询参数，不提供 URL 或 Header 编辑器。
3. 用户点击“测试当前接口”。
4. 浏览器通过同源 `fetch`、当前 Cookie 和当前数据环境调用固定路径。
5. 运行期间按钮显示“正在测试”且不可重复点击；用户切换接口时取消旧请求。
6. 完成后展示状态、耗时、`requestId`、数据环境、测试时间和脱敏预览。
7. 再次测试替换当前接口的旧结果，不持久化真实响应。

## 组件复用

- `PageHeader`：继续承担说明书页标题与说明。
- 现有说明书分类按钮与文档搜索：保留行为和视觉，不新建第四套路由系统。
- 现有 `Button`、状态标签、空状态、错误提示和代码排版：按适用状态复用。
- `react-markdown`：继续渲染正式契约正文，但不负责 API 目录筛选、实测和安全裁剪。

## 新增组件

### `ApiCatalogWorkspace`

- 职责：组合筛选、列表、详情和只读实测。
- 输入：校验后的 API 登记表、当前会话可见状态。
- 状态：筛选条件、选中接口、测试参数、测试结果和运行状态。
- 键盘：筛选控件按 DOM 顺序聚焦；接口列表使用原生按钮；选择后焦点不被强制移动。
- 边界：不直接维护接口事实，不允许调用登记表之外的 URL。

### `ApiEndpointList`

- 职责：显示匹配接口和结果数。
- 状态：加载、空、选中、契约待补充、已停用。
- 键盘：每项为可聚焦按钮，Enter/Space 选择。

### `ApiContractDetail`

- 职责：按固定章节展示机器字段、示例和 Markdown 契约入口。
- 属性：单个接口定义、复制回调。
- 边界：缺失字段显示“契约待补充”，不生成推测内容。

### `ApiLiveTestPanel`

- 职责：渲染允许参数并执行固定只读请求。
- 属性：接口的 `liveTest` 定义、当前数据环境。
- 状态：待测试、运行中、成功、权限不足、超时、网络失败、响应截断。
- 边界：只接受已校验的 `GET` 定义；运行时再次 fail closed。

## 机器目录设计

`docs/platform/api-registry.json` 是 UI 和自动检查共用的结构化目录，不取代 `docs/platform/apis/*.md` 的完整契约。

```json
{
  "version": 1,
  "apps": [
    { "id": "company-platform", "label": "公司平台", "order": 10 }
  ],
  "endpoints": [
    {
      "id": "product-catalog.list",
      "appId": "data-center",
      "method": "GET",
      "path": "/api/platform/v1/product-catalog",
      "title": "读取商品主数据",
      "summary": "按当前权限读取共享商品目录。",
      "status": "available",
      "authentication": "现有登录会话",
      "permission": "由 product-catalog 路由服务端校验",
      "contract": "docs/platform/apis/product-catalog-v1.md",
      "examples": {
        "request": {
          "query": { "page": 1, "pageSize": 20 }
        },
        "success": {
          "source": "contract-test",
          "body": {}
        },
        "errors": []
      },
      "liveTest": {
        "enabled": true,
        "query": ["page", "pageSize"],
        "defaults": { "page": 1, "pageSize": 20 },
        "timeoutMs": 15000
      }
    }
  ]
}
```

上例只说明结构。实施时 `success.body` 必须替换为当前契约测试或正式文档中的完整安全示例，不能保留空对象。

## 真实示例来源

示例按以下优先级提取并写回登记表：

1. 当前路由的契约测试输入与断言。
2. `docs/platform/apis/*.md` 中已评审的请求与响应。
3. 路由解析器和领域规范化函数明确接受、返回的字段。

每个示例记录 `source`，用于自动检查和详情展示。生产响应只在用户主动测试时临时展示，不复制为静态文档样例。

## 只读实测安全边界

- 只允许当前页面同源请求。
- 方法必须严格等于 `GET`。
- 路径必须来自已经通过校验的登记项。
- 只允许登记的查询参数；空值不发送。
- 不允许自定义 Header，不读取或输出浏览器 Cookie、Token 或存储。
- 使用 `AbortController` 执行 15 秒默认超时。
- 响应先限制读取大小，再解析和递归脱敏。
- 敏感键名匹配密码、密钥、Secret、Token、Cookie、Authorization、Session、验证码、手机号和身份证等公司安全规则时返回固定遮罩。
- 数组最多 20 项；最终预览最多 100 KiB。
- HTML 响应不插入 DOM，只作为截断纯文本显示。
- 实测结果只保留在当前页面内存，切页或刷新后消失。

## 页面状态

- 加载：筛选栏可见，列表和详情显示稳定骨架。
- 空数据：说明当前筛选没有接口，并提供“清除筛选”。
- 错误：区分目录加载失败、契约待补充和实测失败；目录失败不影响其他说明书分类。
- 无权限：静态契约继续显示；实测区显示原 API 的 403 安全错误与 `requestId`。
- 禁用：非 `GET`、未登记、契约待补充和已停用接口显示具体禁用原因。
- 成功：显示 HTTP 状态、耗时、测试时间、数据环境和响应预览。
- 超时：显示“接口在 15 秒内未返回”，允许重新测试。
- 截断：明确标记数组或响应已限量，不暗示预览是完整响应。

## 响应式与钉钉 WebView

- 1440–1024 px：接口列表与详情并排，详情区域最小宽度为 0，代码块自身横向滚动。
- 1023–768 px：列表宽度收窄，筛选控件自动换行。
- 767 px 以下：改为单列；先显示筛选和接口列表，选择接口后在列表下方展示详情。
- 不设置整页固定最小宽度；页面不得出现横向溢出。
- 原生选择控件、输入框和按钮保持至少 44 px 触控高度。
- 底部操作区考虑 `env(safe-area-inset-bottom)`，不依赖 `100vh`。

## 交互文案

- 分类：`API 目录`
- 页面说明：`按 App 查找公司已登记的接口、真实契约和当前只读调用结果。`
- 只读按钮：`测试当前接口`
- 运行中：`正在测试…`
- 写接口提示：`说明书只展示写请求示例，不会执行 POST、PUT、PATCH 或 DELETE。`
- 契约缺失：`契约待补充：当前没有足够证据展示 Input 或 Output。`
- 权限不足：`当前身份无权读取该接口；说明书不会绕过服务端权限。`
- 响应截断：`为保护页面性能与数据安全，仅显示限量预览。`

## 无障碍

- 顶部分类使用语义按钮并暴露当前选中状态。
- App、方法和状态筛选都有可见标签。
- 接口选中状态同时使用文字、边框和 `aria-current`，不只依赖颜色。
- 方法标签保留 `GET`、`POST` 等文本。
- 代码块复制按钮具有包含接口与区块名称的可访问名称。
- 实测结果使用 `aria-live="polite"`；错误使用 `role="alert"`。
- 加载中不移动焦点；关闭错误或清除筛选后焦点返回触发控件。
- 支持 `prefers-reduced-motion`，不为列表和响应高度添加布局动画。

## 视觉验收

1. 1440 px：全部 App、已选接口、完整详情和成功实测结果。
2. 1024 px：筛选换行、列表/详情并排、长路径与代码块。
3. 390 px：单列目录、接口详情、复制按钮和响应截断。
4. 状态：加载、空、目录错误、契约待补充、403、超时、成功、写接口禁用。
5. 钉钉 WebView：顶部分类、代码滚动、触控尺寸、安全区和返回路径。
