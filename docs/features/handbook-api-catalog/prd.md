## 背景与问题

说明书当前把 API 目录作为“平台能力”中的一篇长文档展示。`docs/platform/api-catalog.md` 同时罗列多个业务 App 的接口，已超过适合连续阅读的长度；`docs/platform/apis/` 中已有的版本化契约又没有完整进入说明书目录。

使用者因此难以回答三个基本问题：

1. 某个 App 现在可以调用哪些接口。
2. 接口真实接受什么 Input、返回什么 Output。
3. 当前登录身份下，某个只读接口是否仍可正常使用。

静态示例也容易与当前路由、契约测试和真实返回漂移。写接口如果提供一个可随意执行的调试台，又会把说明书变成生产写操作入口，越过现有权限、幂等和确认边界。

## 目标

1. 在说明书顶部将“API 目录”提升为“平台能力”之后的独立分类。
2. 按业务 App 组织接口，支持搜索、筛选和逐个查看完整技术契约。
3. 展示来自当前路由、契约测试或正式 API 文档的真实请求与响应示例。
4. 允许白名单内的同源只读 `GET` 使用当前登录身份和当前数据环境进行实测。
5. 为 `POST`、`PUT`、`PATCH`、`DELETE` 提供完整、可复制但不可在页面执行的真实示例。
6. 用机器可校验的登记表约束 App 归属、契约来源、示例、状态和实测白名单，避免 UI 与文档各维护一套目录。

## 非目标

- 不建设 Swagger、Postman 或支持任意 URL、Header、Body 的通用 API 控制台。
- 不在说明书中执行任何写请求。
- 不读取、展示或保存密码、Cookie、Token、Authorization、验证码或 Provider 原始敏感响应。
- 不因为目录存在就把 `planned`、`integrating` 或契约缺失接口标记为已接通。
- 不在本期新建 D1 表、Secret、服务端 API 或外部平台连接。
- 不一次性重写所有已有 API 路由或改变其响应契约。

## 用户与权限

- 已登录员工：可以查看自己有权看到的说明书与静态 API 契约。
- 具有某接口读取权限的员工：可以实测该接口登记过的只读 `GET`；服务端继续按原接口权限返回数据或 403。
- 没有接口权限的员工：仍可阅读不含敏感信息的契约，但实测结果显示权限不足，不绕过服务端授权。
- 开发与平台维护者：通过仓库中的 API 登记表和版本化契约维护目录；页面不提供在线编辑。

静态契约可见不等于业务数据可见。隐藏按钮不是授权边界，所有真实请求仍由原 API 路由执行认证和权限校验。

## 当前流程

1. 用户进入说明书“平台能力”。
2. 用户打开一篇混合多个 App 的 API 总目录。
3. 用户再到仓库、代码或测试中寻找详细 Input、Output 和错误码。
4. 用户需要离开说明书，用其他工具手工验证接口是否可用。

## 目标流程

1. 用户进入说明书，选择“API 目录”。
2. 页面默认显示全部接口，并可按 App、关键词、方法和状态筛选。
3. 用户选择一个接口，在同一工作区查看认证、权限、Input、请求示例、Output、成功响应、错误码和契约来源。
4. 对登记为可实测的 `GET`，用户填写登记过的查询参数后点击“测试当前接口”。
5. 页面显示 HTTP 状态、耗时、`requestId`、当前数据环境和脱敏后的真实响应预览。
6. 对写接口，页面只显示完整可复制示例和明确的“说明书不执行写请求”提示。

## 业务规则

1. 顶部分类顺序固定为“使用手册 → 产品与设计 → 平台能力 → API 目录”。
2. API App 分组固定为“公司平台、产品全周期、供应链、数据中心、电商运营、品牌内容、人事绩效”；未知 `appId` 由自动检查拒绝，不自动归入“其他”。
3. 共享认证、环境、协同、研发待办等跨 App API 归入“公司平台”，不在各业务 App 重复登记。
4. 接口状态至少区分“可用、接入中、兼容接口、契约待补充、已停用”；只有真实路由、契约和验证证据一致时才显示“可用”。
5. 每个接口使用稳定目录 ID；同一 `method + path` 不得重复登记。
6. 静态请求和响应示例必须来自当前路由代码、契约测试或正式 API 文档，禁止根据名称猜测字段。
7. `GET` 实测必须同时满足：登记表显式开启、同源固定路径、查询字段在白名单、当前登录会话有效。
8. 页面不得接受自定义 URL、自定义 Header、任意请求体或任意 HTTP 方法。
9. `POST`、`PUT`、`PATCH`、`DELETE` 永远不显示执行按钮；示例必须包含方法、路径、必要 Header、Body、成功响应和主要错误。
10. 真实响应在展示前递归遮罩敏感字段；数组最多预览 20 项，序列化预览最多 100 KiB，超限时明确说明已截断。
11. 实测超时默认 15 秒；超时、网络失败、401、403、404、409、429 和 5xx 均按真实状态展示，不伪装为目录故障。
12. 契约文件缺失或示例无法解析时，接口显示“契约待补充”，自动检查失败，不能静默省略。

## 数据定义

### App 定义

- `id`：稳定 App 标识。
- `label`：中文展示名称。
- `order`：目录排序。

### 接口定义

- `id`：稳定接口目录 ID。
- `appId`：所属 App。
- `method`：标准 HTTP 方法。
- `path`：固定同源路径，可包含已声明的路径参数。
- `title`、`summary`：接口名称与一句话用途。
- `status`：`available`、`integrating`、`compatibility`、`contract_pending` 或 `retired`。
- `authentication`、`permission`：登录和授权说明。
- `contract`：仓库内正式契约文件路径。
- `examples`：请求、成功响应和错误示例。
- `liveTest`：只读实测开关、允许的查询字段、默认值和超时。

### 实测结果

- `testedAt`：浏览器发起测试的时间。
- `status`：HTTP 状态。
- `durationMs`：从发起到读取响应的耗时。
- `requestId`：响应中的安全追踪 ID；无值时显示 `—`。
- `dataEnvironment`：响应明确返回或当前页面明确选中的数据环境。
- `body`：脱敏、限量后的 JSON 或文本预览。
- `truncated`：响应是否被截断。

## 异常与边界

- 登记表加载失败：API 目录显示错误状态和重试入口，其他说明书分类继续可用。
- 无接口记录：说明当前筛选没有匹配项，并提供清除筛选。
- 契约待补充：可以查看已有路径和状态，但不显示伪造 Input、Output，也不能实测。
- 无权限：真实请求返回 403，页面保留 `requestId` 和安全错误，不建议更换身份绕过。
- 未登录或会话过期：显示需要重新登录，不改用匿名请求。
- 非 JSON 响应：仅显示限量文本与 Content-Type，不渲染 HTML。
- 响应含敏感字段：键名命中密码、密钥、Token、Cookie、Authorization、会话、验证码等规则时，以固定遮罩替换值。
- 数组或响应过大：只展示安全上限内的预览，并显示完整响应未进入页面状态。
- 写接口：复制不产生请求；用户必须在业务 App 或受治理的外部工具中按原权限执行。
- 历史深链：已有说明书文档 slug 和三类顶部分类保持兼容。

## 验收标准

1. 说明书顶部出现独立“API 目录”，位于“平台能力”之后。
2. `docs/platform/apis/*.md` 的允许展示文档进入构建目录，用户可从接口详情打开对应契约。
3. API 目录可按七个 App 分组、关键词、方法和状态筛选。
4. 接口详情按“基础信息 → Input → 请求示例 → Output → 成功响应 → 错误码 → 契约来源”展示。
5. 至少覆盖当前正式契约中的主要接口；未完成的接口显示真实状态，不把 `planned` 当 `available`。
6. 白名单内的同源 `GET` 能在当前登录身份下实测，并展示状态、耗时、`requestId`、数据环境和脱敏响应。
7. 页面无法输入任意 URL、Header 或方法；未登记和非 `GET` 接口不能执行。
8. 所有写接口提供来自当前契约的可复制请求与成功响应示例，页面没有写请求执行入口。
9. 自动检查能拒绝未知 App、重复接口、无效方法、失效契约路径、无效 JSON 示例、敏感示例和越权实测配置。
10. UI 覆盖加载、空、错误、无权限、禁用、超时、响应截断、键盘焦点、窄屏和钉钉 WebView。
11. 现有说明书深链、平台能力专题面板和 Markdown 阅读功能不回归。
12. lint、治理、集成、环境能力、完整测试、构建和 Pages Functions 兼容检查通过。

## 上线与回滚

- 本期没有数据库迁移、Secret 或新服务端路由。
- API 登记表与代码同版本发布；目录生成或校验失败时阻止合并。
- 发布后通过固定 `dev` 站点先验收目录、示例和只读实测，再由 `dev → main` 发布生产。
- 回滚时移除独立分类和专用工作区，恢复现有平台能力目录；版本化 API 契约文档保留，不删除。
- 实测开关可以逐接口关闭；关闭不影响静态契约阅读和原业务 API。
