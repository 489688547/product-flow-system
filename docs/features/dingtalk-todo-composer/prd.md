# 钉钉待办编排器 PRD

## 文档状态

- 状态：完成入口修复待生产验收
- 负责人：产品负责人
- 最近更新：2026-07-28

## 背景与问题

产品进度中的任务可以同步为钉钉待办，但当前流程仍要求用户记住群名，缺少“我的群”默认入口；发送前只能选择执行人，不能核验或调整待办标题、正文、优先级和具体截止时间。没有截止日期时入口直接禁用，也没有修复路径。群成员身份无法确认时只显示跳过人数，用户无法判断漏发对象。

## 目标

- 群聊模式默认展示当前用户创建或管理的群，并保留关键词搜索。
- 选择群后明确展示最终执行人、来源群、去重结果和跳过成员原因。
- 发送前可编辑标题、富文本正文、优先级、截止日期和具体时间。
- 没有任务截止日期时仍可进入弹窗并完成补录。
- 发送或更新钉钉待办后保存最后一次编排内容，下一次更新可继续编辑。
- 以钉钉为主回流已同步任务的完成状态、标题、正文、优先级、截止时间和执行人。
- 钉钉工作待办卡片展示明确的“完成任务”入口；进入系统后精准定位产品、阶段和任务，并由一次确认同时完成系统任务和钉钉待办。
- 钉钉创建成功时由服务端把真实 todoId 与任务绑定在同一次业务流程中持久化，不依赖浏览器随后保存整份共享状态。
- 展示数据库只显示“展示模拟”，不得把模拟动作标成真实“已同步”。
- 覆盖加载、空数据、授权失败、接口失败、提交禁用、键盘和窄屏状态。

## 非目标

- 不把待办直接发送到群会话；群聊仅作为执行人选择来源。
- 不创建、修改或解散钉钉群。
- 不在本次实现附件、子待办、评论、循环待办或独立提醒规则。
- 不把其他应用或未绑定产品任务的个人待办写回产品流程。

## 用户与权限

- 能编辑产品进度任务的企业成员可以打开编排器。
- 钉钉群列表和成员读取使用当前登录用户的授权令牌，只返回其可见群。
- 群成员必须精确映射到当前企业有效组织成员并具有 unionId，才可成为执行人。
- 服务端继续校验会话、令牌、请求方法和必填参数；前端隐藏或禁用不是权限边界。

## 当前流程

1. 用户为任务设置截止日期。
2. 点击“未同步”。
3. 按人员选择，或输入群名搜索并读取群成员。
4. 点击发送，系统用固定标题、纯文本正文、普通优先级和当天 18:00 创建待办。

## 目标流程

1. 用户点击“未同步/待更新”，无论任务是否已有截止日期都可打开编排器。
2. 系统生成标题、正文、普通优先级和截止时间默认值；已同步任务恢复上次编排内容。
3. 用户按人员选择，或进入群聊模式直接查看“我的群”，也可搜索其他可见群。
4. 选择群后，系统读取并合并可识别企业成员；用户可以逐人排除，并查看跳过成员及原因。
5. 用户核对最终执行人和待办预览，编辑标题、富文本正文、优先级、日期及时间。
6. 系统校验标题、正文、截止时间和至少一名执行人，再创建或更新同一条钉钉待办。
7. 钉钉成功后，服务端基于最新共享状态合并 todoId、来源、创建人、执行人、草稿和同步快照；并发版本冲突时重新读取并只重放本任务绑定，不能返回未落库的成功。
8. 成功后前端采用服务端返回的已持久化任务；失败时保留输入并显示可恢复错误。
9. 登录后、窗口重新获得焦点及定时刷新时查询当前用户的钉钉待办，把远端修改回流到对应产品任务。

## 业务规则

- 优先级采用钉钉值：10 低、20 普通、30 较高、40 紧急，默认 20。
- 新待办默认截止时间为任务截止日 18:00；任务无日期时日期为空、发送按钮禁用但弹窗可用。
- 在编排器修改截止日期后，同步更新产品任务截止日期，保持本地任务与钉钉一致。
- 富文本 HTML 仅用于本地编辑和预览；同步钉钉时转换为保留段落、列表和链接文本的可读正文，避免发送 HTML 标签或内嵌图片数据。
- 多群重复成员按 unionId 去重；人工选择优先保留；用户明确排除后，同一弹窗内再次选择群也不自动加回。
- 群聊不是待办接收对象，最终只提交执行人 unionId。
- 新任务使用应用访问凭证创建可查询的钉钉企业工作待办，并在创建请求的 `actionList` 中加入跳转型“完成任务”动作。企业工作待办不会被假定为钉钉原生个人待办；业务完成动作进入已登录的产品流程详情页，由内部写接口同时更新系统任务和钉钉状态。
- 详情链接必须携带 `productId` 和 `taskId`；应用启动后读取并校验参数，自动选择对应产品和阶段、高亮任务。只有 `todoAction=complete` 显示完成确认入口，未知动作降级为只读定位。
- `dingTodo.actionVersion` 记录卡片动作契约版本。已绑定但缺少动作版本的工作待办显示“待更新”；产品负责人、原创建人或执行人重新同步时，先创建受控 `:rN` 新工作待办，再把旧工作待办标记完成以退出未完成列表，避免删除历史记录。
- 只有本地 `dingTodo.sourceId` 与当前产品任务稳定来源完全一致或是该来源的受控恢复版本、且绑定来源为企业工作待办时，才复用 todoId。只有旧 ID、来源无法确认的记录标为“待确认”，重新同步时忽略旧 ID 并创建企业工作待办。
- 2026-07-27 生产真机验证确认：个人待办创建接口返回的 `task…` ID 不进入企业待办查询结果，不能作为双向同步主链路。已绑定个人待办不删除；由服务端确认的产品负责人、原创建人或执行人再次同步时，使用受控 `:rN` 来源创建企业工作待办并替换系统绑定。
- 2026-07-27 生产闭环验收确认：真实企业工作待办可在钉钉完成并回流系统；系统取消完成后会更新同一 todoId 的整体状态与执行者状态，使钉钉恢复未完成，不重复创建待办。历史受控恢复来源即使包含多段严格 `:rN` 后缀，也只作为同一任务的兼容迁移链路。
- 回流以企业工作待办为主；过渡期仍可读取当前登录用户可见的个人待办，但只按本地已保存的 todoId 或稳定 sourceId 绑定产品任务；其他个人待办、Teambition 项目任务和其他应用对象不得误绑定。
- 远端待办缺少修改时间时，使用远端业务字段快照去重；完成状态、标题、优先级和截止时间有变化才写回，重复刷新不得制造共享状态写入。
- 未完成与已完成列表串行执行并分别有界分页；同一浏览器内重叠的首次加载、窗口聚焦和定时刷新合并为单次请求。按查询列表归一完成状态，远端完成状态、正文、优先级、截止时间和执行人覆盖本地同步快照，钉钉查询失败时保留最后一次成功状态。
- 钉钉返回任务 ID 只表示创建请求受理，不等同于客户端通知送达回执；界面不得把它描述成执行人已收到通知。
- “完成任务”卡片动作只负责导航，不允许 GET 请求直接修改状态；最终完成必须在已登录业务页由用户确认，继续经过服务端权限、稳定来源、todoId 和幂等校验。
- 产品任务的远端绑定以服务端成功持久化为准。钉钉已创建但绑定暂时无法写入时，接口必须返回明确的部分成功错误，不能让前端显示“已同步”。
- 展示数据库的外部动作模拟记录保存 `simulated=true`，任务状态显示“展示模拟”；模拟 todoId 不参与正式钉钉回流。

## 数据定义

- `subject`：待办标题，1-1024 字符。
- `descriptionHtml`：本地富文本草稿，禁止内嵌图片和脚本。
- `description`：由富文本转换的钉钉正文纯文本。
- `priority`：10/20/30/40。
- `dueDate`：`YYYY-MM-DD`。
- `dueClock`：`HH:mm`，默认 `18:00`。
- `dueTime`：按 Asia/Shanghai 组合后的毫秒时间戳。
- `groups`：已选群的 ID、名称、成员数、跳过信息；不传给待办 API。
- `dingTodo.draft`：最后一次成功同步的标题、富文本正文、优先级、日期和时间。
- `dingTodo.actionVersion`：钉钉工作待办卡片动作契约版本；当前为 `1`。

## 异常与边界

- 我的群为空：展示解释性空态和搜索入口。
- 用户授权失效：显示重新授权链接，保留已填写草稿。
- 群成员包含外部联系人、离职人员、机器人或无法映射身份：不加入执行人，展示具体姓名与原因摘要。
- 新群搜索开始时清空旧结果；搜索失败不显示旧结果。
- 群成员读取期间锁定其他群选择，防止并发状态错乱。
- 组织缓存晚到时，保留用户已做的选择，只补齐尚未初始化的已同步执行人。
- 提交期间所有模式、搜索、添加和移除操作均禁用。
- 历史记录只有 `todoId`、没有稳定 `sourceId`：显示“待确认”；再次同步时忽略旧 ID 并按稳定来源新建本应用待办。
- 钉钉成功后共享状态发生并发更新：服务端重新读取最新状态，仅合并当前任务的 `dingTodo` 和同步后的截止日期；连续冲突后返回可重试错误并保留真实 todoId 供审计，不报告完整成功。

## 验收标准

- 打开群聊模式且搜索为空时，自动请求并展示我的群。
- 搜索“产品”时能展示匹配群，清空搜索后恢复我的群。
- 选择两个有重复成员的群，最终执行人不重复；移除一群不误删其他来源成员。
- 任务无日期时可打开弹窗，在弹窗内设置日期和时间后发送按钮启用。
- 预览显示最终标题、正文、优先级、完整截止时间和执行人数量。
- 新建企业工作待办时稳定来源、正文、截止时间、优先级、执行人和产品进度详情链接进入官方创建请求。
- 新建企业工作待办的 `actionList` 包含“完成任务”，动作 URL 增加 `todoAction=complete`，默认详情 URL 不包含完成动作参数。
- 从“完成任务”进入后自动选中链接中的产品和任务所在阶段，高亮对应任务并聚焦完成按钮；确认后同一次同步把系统任务和钉钉待办设为已完成。
- 历史工作待办缺少 `actionVersion` 时显示“待更新”；授权人员重新同步后绑定新的可操作 todoId，旧 todoId 进入已完成列表且不被删除。
- 更新已绑定的企业工作待办时保持 todoId 与稳定来源，不重复创建；完成状态同时写入待办整体状态和执行者状态接口，使系统取消完成后钉钉端重新进入未完成列表。
- 已绑定的个人待办、历史 Teambition/其他应用或来源不明的待办 ID 不会继续作为双向同步主绑定；可信任务负责人重新同步后获得可查询的企业工作待办。
- 在钉钉修改并完成待办后，页面重新聚焦即开始回流；待办位于当前查询窗口时在一次轮询内同步，待办较多时按有界游标逐轮覆盖后同步。系统必须明确显示授权失效、限流与覆盖不完整状态，不能把未覆盖误报为已同步。
- 钉钉创建成功后，即使浏览器整表保存发生版本冲突，正式数据库仍保存同一个真实 todoId；刷新页面后任务保持绑定并能回流完成状态。
- 展示数据库点击发送后显示“展示模拟”，钉钉客户端不会收到任务，界面也不出现绿色“已同步”。
- 键盘用户进入弹窗后焦点位于弹窗内，Tab 不离开弹窗，Escape 关闭并恢复触发按钮焦点。

## 上线与回滚

- 不新增数据库表；服务端复用现有共享状态原子基线写入。旧任务没有 `dingTodo.draft` 时使用任务字段生成默认值。
- 新字段均为可选，旧状态向后兼容。
- 回滚前端编排器和我的群 API 即可恢复旧流程，已同步钉钉待办不受影响。
- 通过 GitHub `main` 和 Cloudflare Git 集成发布；发布后分别验证生产登录态、钉钉完成回流、系统恢复未完成和正式数据库绑定。
