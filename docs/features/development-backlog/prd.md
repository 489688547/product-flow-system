# 研发待办 PRD

## 文档状态

- 状态：已评审，开发中
- 归属：平台
- 最近更新：2026-07-24

## 问题

研发需求、后续事项、分支占用和验收结果分散在对话与代码中，不同开发任务无法可靠判断是否正在修改同一模块。公司需要一个所有员工可见、由总经办治理、开发任务可以认领和更新的统一研发控制面。

## 目标

- 在“平台”新增“研发待办”，位于“说明书”之后。
- D1 保存结构化事项与追加事件，跨设备和分支读取同一状态。
- 所有员工可查看，总经办创建、定优先级、验收和关闭。
- 非只读员工可认领事项；负责人或总经办推进开发状态。
- 按模块和仓库相对路径阻止活跃任务冲突。
- AI 总助把自然语言讨论整理成草稿，用户确认后才写入。

## 非目标

- 不替代钉钉待办、部门协同或 GitHub Issues。
- 不自动创建分支、PR 或合并代码。
- 不保存完整 AI 对话、Prompt、模型原始响应或未确认草稿。
- 不用于工时统计、绩效排名或展示环境演示。

## 权限

- 已登录员工：查看、筛选、使用 AI 讨论。
- 非只读员工：认领和更新本人开发事项。
- 总经办：新增、编辑需求、调整优先级、验收、关闭、取消和重开。
- 所有写权限由服务端验证。

## 状态

`待澄清 → 待开发 → 开发中 → 待验收 → 已完成`，活跃事项可进入“已阻塞”，事项可由总经办取消或重开。提交验收必须有证据；完成必须由总经办确认。

## 验收

1. 所有员工看到同一 D1 列表，筛选只有点击查询才执行。
2. 无权限写入返回稳定安全错误。
3. 重叠模块或路径不能同时认领。
4. 每次写入有版本检查和追加事件。
5. AI 未配置跳到 AI 大模型，临时失败留在当前页。
6. AI 草稿未经总经办确认不会入库。
7. 展示数据库策略为 `skip`，不得回退正式库。
