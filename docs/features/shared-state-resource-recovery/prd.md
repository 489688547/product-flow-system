# 共享状态资源超限修复 PRD

## 文档状态

- 状态：已确认
- 负责人：平台研发
- 最近更新：2026-07-29

## 背景与问题

产品全周期把产品图片以内嵌 Data URL 保存到共享状态。同一张图片会继续复制到需求、产品、默认封面交付物和规划快照。当前线上一张约 292 KB 的 PNG 被保存四次，使 `/api/state` 响应约 1.2 MB。Cloudflare Worker 在读取时先解析全部分片，再把完整对象重新序列化，连续触发 `1102 Worker exceeded resource limits`，页面无法读取或保存共享状态。

同时，旧钉钉待办记录可能缺少当前动作版本。业务内容没有变化时仍显示“待更新”，用户会误以为同步失败。

## 目标

- `/api/state` 读取大状态时不再对完整业务对象执行一次解析和一次重新序列化。
- 写前快照直接复用已持久化的状态分片，不再把完整状态重新序列化为单个大字符串。
- 产品图片在进入共享状态前缩放并压缩，避免新的超大 Data URL。
- 通过受控生产数据网关压缩当前重复图片并修复已确认的旧待办动作版本，保留全部业务记录。
- 正式站冷读、热读、保存及钉钉待办状态均可验证。

## 非目标

- 不删除需求、产品、产品规划或交付物记录。
- 不新增对象存储、D1 表、环境变量或 Cloudflare 绑定。
- 不改变图片显示位置、产品规划交互或钉钉 Provider 合同。
- 不把共享状态迁移成新的业务实体模型。

## 业务规则

- 产品封面上传最长边不超过 640 像素；优先使用浏览器可生成的 WebP，并把 Data URL 控制在约 120,000 字符以内。
- 压缩失败时不得静默保存超大原图；界面显示可恢复错误，用户可重新选择图片。
- 现有图片修复只替换内容相同的重复 Data URL，不改变业务记录、名称、关联和顺序。
- 旧待办只有在远端绑定、执行人状态覆盖和当前快照均存在时，才允许补齐动作版本；不得伪造完成状态。
- 所有生产修复必须经过个人令牌、最高权限身份、15 分钟解锁、基线校验、写前快照和审计。

## 验收标准

- 带 1 MB 以上内嵌图片的分片可由 `GET /api/state` 返回有效 JSON，读取路径不解析分片业务值。
- 写前快照可从数据库分片生成，并能完整回滚。
- 1600×800 图片上传后保存为不超过 640×320 的压缩图片。
- 当前线上四份重复图片压缩后，状态字符数显著下降且四个业务位置仍可显示。
- “立项PRD同步”在内容没有变化时不再显示“待更新”，执行人完成状态保持真实。
- 正式站 `/api/state` 冷读、热读和 20 并发请求不返回 1102。

## 上线与回滚

- 先合入 `dev` 并在固定测试站验证，再由唯一 `dev → main` PR 发布。
- 数据修复在代码发布后通过生产网关执行；写前快照和审计 ID 必须保留。
- 若数据验证失败，使用对应审计记录回滚；若代码验证失败，回滚 Pages 部署，不回滚已验证有效的压缩数据。
