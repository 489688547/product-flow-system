# 研发待办设计提案

## 文档状态

- 状态：已确认，待实施计划评审
- 归属：平台
- 日期：2026-07-24

## 背景

公司经营平台已经由多个开发任务和分支持续演进，但后续需求、已确认决策、开发占用范围和验收状态目前分散在对话、任务和代码分支中。不同开发任务无法稳定判断同一模块或文件是否已被占用，已完成事项也缺少统一验收与关闭记录。

研发待办需要成为公司内部开发协作的控制面：

- 员工能看到产品还要做什么、谁在做、做到哪一步。
- 总经办与 AI 总助能把已确认讨论转换成结构化需求。
- 开发任务在开始编码前认领待办，避免多个分支修改同一范围。
- 完成、阻塞、取消和重新打开都有可追溯记录。
- 研发待办只管理研发协作，不混入钉钉待办、经营任务或数据同步任务。

## 目标

- 在左侧“平台”下新增独立“研发待办”页，位于“说明书”之后、“问题反馈”之前。
- 使用 D1 作为唯一主数据源，让不同设备、任务和分支读取同一状态。
- 所有已登录员工可查看；总经办负责创建、编辑优先级、验收、关闭和重新打开。
- 开发人员可认领、释放、更新开发状态、填写分支与验收证据。
- 在认领前检测模块和受影响路径冲突，并给出明确冲突对象。
- 通过 AI 总助讨论生成结构化草稿，必须由用户确认后才写入数据库。
- AI 不可用时提供可恢复路径，不阻断手工新增。

## 非目标

- 不用 GitHub Issues、钉钉待办或本地 Markdown 作为主数据源。
- 首版不创建 GitHub Token，不自动创建分支、提交、Pull Request 或合并代码。
- 不把研发待办做成通用项目管理、工时、绩效或员工排名系统。
- 不保存完整 AI 对话、Prompt、模型原始响应或未确认草稿。
- 不允许浏览器直接访问模型 Provider、持有模型密钥或自行判断 AI Feature。
- 不将研发待办复制到展示数据库，也不随业务数据环境切换。

## 产品定位

研发待办属于公司平台控制面，不属于任何单一业务 App。它记录产品研发意图、开发占用和验收结果，可以被公司平台页面、AI 总助和受控开发工具共同消费。

该能力按共享平台能力建设：

- 页面只负责查询、操作和展示。
- 状态流转、权限、冲突判断和编号生成位于领域与服务端边界。
- D1 表、鉴权、审计和错误契约由平台 API 统一管理。
- 后续其他研发入口必须复用同一 API，不得另建浏览器本地待办列表。

## 页面结构

### 顶部

- 标题“研发待办”及简短说明。
- 主按钮“和 AI 总助讨论新增”。
- 次按钮“手工新增”，只对总经办显示；这是 AI 不可用时的简化兜底。
- 状态计数：待澄清、待开发、开发中、待验收、已阻塞。

### 查询区

支持状态、优先级、模块、负责人筛选和编号/标题关键字搜索。选择筛选条件只更新查询条件，点击“查询”或“刷新”后才请求服务端。

### 列表

首版采用紧凑表格，不采用看板。主要列：

- 待办编号
- 标题
- 模块
- 优先级
- 状态
- 负责人
- 分支
- 最近更新
- 冲突状态
- 操作

表头筛选遵循平台表格规则：列名旁使用图标触发筛选或排序，不在表头重复展示已选值胶囊。

默认排序为：

1. 已阻塞和检测到冲突的事项优先。
2. `P0` 到 `P3`。
3. 最近更新时间倒序。

关闭和取消项默认隐藏，可通过状态筛选查看。列表使用服务端分页。

### 详情抽屉

点击一行打开详情抽屉，显示：

- 背景与目标
- 验收标准
- 模块与受影响路径
- 依赖项
- 当前负责人、分支和可选 PR 链接
- 验收证据
- 冲突说明
- 完整状态历史
- 创建来源：AI 总助、Codex 或手工

详情抽屉不显示 AI 原始对话、Prompt、模型响应、凭据、Cookie 或其他敏感上下文。

## 待办状态

主状态：

- `clarification`：待澄清
- `ready`：待开发
- `in_progress`：开发中
- `review`：待验收
- `completed`：已完成
- `blocked`：已阻塞
- `cancelled`：已取消

允许的主要流转：

```text
待澄清 → 待开发 → 开发中 → 待验收 → 已完成
   └──────→ 已取消
待开发 / 开发中 / 待验收 → 已阻塞
已阻塞 → 待开发 / 开发中
已完成 / 已取消 → 待开发
```

业务规则：

- 新增项缺少明确验收标准或影响范围时必须进入“待澄清”，不能直接认领。
- 认领“待开发”会原子写入负责人、分支和状态“开发中”。
- 提交验收前必须填写安全的验收证据摘要；PR 链接可选，运维或数据修复事项可以没有 PR。
- 只有总经办可以将“待验收”改为“已完成”。
- 阻塞必须填写阻塞原因和恢复条件。
- 取消和重新打开必须填写原因。
- 已完成、已取消项不参与开发冲突判断。

## AI 总助新增流程

### 正常流程

1. 用户点击“和 AI 总助讨论新增”。
2. 页面打开 AI 讨论抽屉，用户使用自然语言描述需求。
3. 服务端通过共享 `invokeAiFeature` 边界调用已登记能力：
   - `appId: company-platform`
   - `featureId: development-backlog-draft`
4. AI 返回可编辑的结构化草稿：
   - 标题
   - 背景与目标
   - 模块
   - 优先级建议
   - 验收标准
   - 受影响路径
   - 依赖
   - 建议初始状态
5. 页面标明“AI 建议”，用户可继续讨论或修订。
6. 只有总经办点击“确认写入研发待办”后，页面才调用新增 API。
7. 服务端重新校验字段、权限和冲突范围，生成稳定编号并写入 D1。

讨论阶段只保存在当前浏览器短时内存。刷新、关闭抽屉或离开页面时不自动保存；只有未提交的原始需求描述可用于配置页往返恢复，完整对话和 AI 原始输出不持久化。

### AI 未配置

当服务端明确返回 Feature 未登记、Provider 未配置、凭据不可用或能力被禁用时：

- 不打开一个无法继续的空讨论框。
- 导航到“数据中心 → AI 大模型”配置页面。
- 带安全的返回目标和来源提示，配置成功后可以返回研发待办。
- 只在会话存储中恢复用户尚未提交的需求描述，不恢复完整讨论。
- 页面仍保留总经办可用的“手工新增”。

### 临时失败

当发生超时、限流或 Provider 临时波动时：

- 留在研发待办页面。
- 保留当前需求描述。
- 显示安全错误摘要、重试按钮和手工新增入口。
- 不把临时失败误判为“未配置”，不自动跳转。

### AI 安全边界

- 浏览器不持有 Provider URL、Secret、Authorization Header 或 Responses adapter。
- 未登记的 AI Feature 以 `AI_FEATURE_NOT_REGISTERED` 失败关闭。
- AI 审计只记录稳定 App、Feature、执行模式、是否调用 Provider、Token 数量和安全结果码。
- Prompt、回答、业务上下文、Skill 参数和 Provider 原始响应不进入 AI 审计。
- AI 结果始终是草稿，不能自行创建、认领、关闭或提高待办优先级。

## 手工新增

总经办可使用简化表单新增：

- 标题
- 背景与目标
- 模块
- 优先级
- 验收标准
- 受影响路径
- 依赖项

除标题外，缺失关键字段时允许保存为“待澄清”。手工表单和 AI 确认共用同一新增 API、校验和编号生成逻辑。

## 冲突检测与认领

### 影响范围表达

- `module` 使用代码登记的稳定模块 ID，不接受任意显示名称作为身份值。
- `scopePaths` 使用仓库相对路径前缀，例如 `src/features/platform-backlog/`。
- 不保存用户电脑的绝对路径。
- 不支持由前端自由提交 glob、正则或脚本。
- 范围未知或过宽时保持“待澄清”，不能认领。

### 冲突规则

服务端只对 `ready`、`in_progress`、`review`、`blocked` 的待办进行冲突判断。满足任一条件视为冲突：

- 两项的规范化仓库相对路径相同。
- 一项路径是另一项路径的目录前缀。
- 两项模块相同，且任一项尚未给出足以区分的路径范围。

路径在比较前移除重复分隔符、`.` 段和首尾 `/`；包含 `..`、绝对路径或控制字符的输入直接拒绝。

### 认领

认领请求必须携带：

- 待办 ID
- 当前版本号
- 符合仓库分支命名规则的分支名

服务端在同一原子操作中重新读取当前记录、检查状态、版本和冲突，再写入负责人、分支、状态与事件。发现冲突时返回：

- 冲突待办编号与标题
- 冲突模块或安全路径前缀
- 当前负责人和分支
- 建议动作：调整范围、释放原任务或由总经办确认拆分

首版不提供“强制忽略冲突”。总经办调整范围或关闭冲突项后再认领。

## 数据模型

研发待办属于控制平面，存储在 `PRODUCT_FLOW_DB`。它不使用 `businessDatabase(context)`，不随正式/展示业务数据库切换。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | TEXT PK | 事件 UUID |
| `item_id` | TEXT | 关联待办 |

| `actor_user_id` | TEXT | 操作人稳定用户 ID |
| `actor_name_snapshot` | TEXT | 当时显示名快照 |
| `branch_snapshot` | TEXT NULL | 操作时分支 |

| `created_at` | TEXT | UTC ISO 时间 |

事件只追加，不更新、不删除。事件不保存字段的旧秘密值、完整 AI 内容或业务敏感上下文。

### 索引与容量

至少建立：

- `display_id`
- `status, priority, updated_at`
- `module_id, status`
- `owner_user_id, status`
- `item_id, created_at` 事件索引

首版按内部研发待办规模设计，列表使用游标或页码分页，详情历史单独读取，避免列表请求携带全部事件。

### 展示数据策略

两张表在展示数据目录登记为 `skip`：

- 研发待办包含内部路线图、分支、负责人和未发布需求，不复制到展示数据库。
- 未登记表默认 `skip` 的失败关闭规则继续有效。
- 展示模式中页面返回“该控制面在展示环境不可用”，不得回退读取正式库。

### 更新与动作

内容编辑：

```http
PATCH /api/platform/v1/development-backlog/:id
```

状态动作：

```http
POST /api/platform/v1/development-backlog/:id/actions
```

动作请求示例：

```json
{
  "action": "claim",
  "expectedVersion": 3,
  "branch": "codex/douyin-auto-claim"
}
```

支持动作：

- `claim`
- `release`
- `start`
- `submit_review`
- `block`
- `resume`
- `complete`
- `cancel`
- `reopen`

每次写操作都要求 `expectedVersion`。不匹配返回 `409 BACKLOG_VERSION_CONFLICT` 和当前安全快照，客户端提示刷新，不自动覆盖。

### AI 草稿

研发待办页面不新增直连 Provider 的接口。它调用共享 AI Feature 执行边界并传递结构化任务类型；服务端从登记表解析 `company-platform/development-backlog-draft`。AI 返回只用于当前草稿，最终新增仍调用标准新增 API。

## 错误契约

- `BACKLOG_FORBIDDEN`：当前身份无权执行该动作。
- `BACKLOG_NOT_FOUND`：待办不存在。
- `BACKLOG_INVALID_TRANSITION`：状态流转不允许。
- `BACKLOG_VERSION_CONFLICT`：记录已被其他任务更新。
- `BACKLOG_SCOPE_REQUIRED`：范围不足，不能认领。
- `BACKLOG_SCOPE_INVALID`：路径不是安全仓库相对路径。
- `BACKLOG_ACTIVE_CONFLICT`：存在活跃冲突。
- `BACKLOG_BRANCH_INVALID`：分支名不符合规则。
- `BACKLOG_ACCEPTANCE_EVIDENCE_REQUIRED`：提交验收缺少证据。
- `BACKLOG_MODULE_NOT_REGISTERED`：模块未登记。
- `AI_FEATURE_NOT_REGISTERED`：AI 能力未登记，应进入模型配置恢复路径。
- `AI_PROVIDER_UNAVAILABLE`：AI Provider 未配置或不可用。
- `AI_FEATURE_TIMEOUT`：AI 临时超时，留在当前页重试。

错误响应只包含稳定错误码、安全摘要、恢复动作和必要的冲突元数据，不返回堆栈、SQL、模型响应或凭据。

## 状态与交互细节

- 加载：表格骨架和不可重复提交按钮。
- 空数据：说明当前筛选下没有待办，并提供清除筛选；总经办可新增。
- 请求失败：保留当前筛选，显示重试，不清空上一份可信列表。
- 无权限：页面可读，写按钮隐藏或禁用；服务端仍返回 `403`。
- 版本冲突：提示记录已更新，展示刷新按钮，不自动覆盖用户输入。
- 范围冲突：在行和详情中显示冲突待办；认领按钮禁用。
- AI 未配置：跳转模型配置并保留安全返回目标。
- AI 临时失败：原地重试并提供手工兜底。
- 提交中：按钮禁用并避免双击；服务端以版本和幂等策略防止重复事件。
- 成功：列表局部刷新并把新版本写回客户端。

所有状态用文字、图标和颜色共同表达。抽屉、表单、菜单和对话框支持键盘操作、焦点归还和明确焦点环。错误消息通过可感知区域宣布。颜色满足 WCAG AA。

桌面宽度使用紧凑表格；640px 以下按异常和进行中优先改为卡片，但保持同样的字段、权限和动作。钉钉 WebView 中不依赖悬停交互。

## 开发任务协作约束

接入后，受控开发流程为：

1. 开发任务先查询研发待办。
2. 找到已确认事项后读取详情和冲突。
3. 使用实际分支名认领。
4. 开发过程中更新阻塞或范围变化。
5. 完成验证后提交待验收并写安全验收证据。
6. 总经办验收后关闭。

未来需要把该规则写入平台开发文档和适用的 `AGENTS.md` 持久规则，并为 Codex 提供只读查询与受控认领能力。AI 或开发工具不得绕过用户权限，也不得在没有明确确认需求时自行新增产品事项。

## 迁移、兼容与回滚

- 新增向前兼容的 D1 migration，创建两张表和索引，不修改现有业务表。
- API 在表不存在时返回明确能力未部署错误，页面显示不可用，不回退本地存储。
- 迁移需登记 `PRODUCT_FLOW_DB` 绑定、容量影响和展示目录 `skip` 策略，并更新环境能力生成物。
- 回滚前端和 API 不删除表；保留已写事件。需要停用时隐藏导航并关闭写路由。
- 若迁移回滚必须移除表，先导出受控备份并由总经办确认，不能由普通部署脚本自动删除。

## 可观察性与审计

- 每个写动作生成一个追加事件，包含操作者、动作、状态和版本。
- API 日志记录请求 ID、结果码、耗时和待办 ID，不记录正文、验收细节或 AI 内容。
- AI 使用沿用共享安全审计。
- 冲突检测失败、版本冲突和权限拒绝使用稳定结果码统计。
- 数据库错误不得在客户端呈现 SQL 或内部绑定信息。

## 验收标准

- “平台”下出现“研发待办”，位置和权限符合设计。
- 不同登录员工看到相同 D1 待办状态，本地缓存不会覆盖服务端。
- 总经办能新增、调整、验收、关闭和重开；普通员工只能查看。
- 开发人员能使用真实分支认领并更新本人任务。
- 两个重叠模块或路径不能同时被认领，页面能指出冲突来源。
- 每次成功和失败的状态写入都有明确反馈；成功写操作有追加事件。
- AI 草稿未经确认不会产生待办。
- AI 未配置会跳到“数据中心 → AI 大模型”，临时失败留在当前页。
- 页面和 API 不暴露完整 AI 对话、凭据、绝对路径或内部错误。
- 两张表登记展示策略 `skip`，展示模式不回退正式控制库。
- 完成全量 lint、治理、集成、环境能力、测试和构建检查，并通过生产 GitOps 部署后的真实鉴权验收。
