# 抖店罗盘经营数据采集设计提案

## 文档状态

- 状态：待用户书面确认
- 负责人：数据中心 / 运营部
- 日期：2026-07-24

## 背景与范围

抖店后台和电商罗盘已经包含店铺、商品、直播与短视频经营数据，但当前数据中心没有稳定的自动采集结果。运营需要逐页查看或人工下载，老板无法在公司经营平台持续读取同一口径的数据，失败也没有统一同步记录。

2026-07-21 因账号密码登录会动态触发协议、验证码、滑块和设备验证，抖店网页登录任务被退役并改为等待文件样例。2026-07-24 重新确认的范围不是恢复账号密码自动登录，而是复用公司 Chrome 中已经由员工建立的抖店登录态，以官方报表下载为主、固定白名单页面读数为兜底，接入现有公司网页数据采集器。

本阶段范围为：

- 店铺每日总览 `store_daily`
- 商品每日明细 `product_daily`
- 直播每日明细 `live_daily`
- 短视频每日明细 `video_daily`
- 每天上海时间 05:00 采集昨天完整自然日
- 先完成昨天数据真实验收，暂不启动历史回补

## 目标

- 四类资源独立执行、独立失败和独立推进游标。
- 能下载的页面优先使用官方 XLSX/CSV；没有官方明细下载的店铺汇总，仅允许读取代码登记的固定指标。
- 原始文件保存在公司 Mac，D1 只保存标准事实、数据质量、任务状态和安全审计。
- 数据同步页显示成功、失败、等待登录、等待验证、页面变化和恢复动作。
- 数据中心、电商店铺运营和公司经营只读取数据库中的标准事实。

## 非目标

- 不采集订单、物流、售后工单或评论原文。
- 不接入巨量千川广告账户、计划、素材、消耗或付费 ROI；自然经营事实和付费投放事实保持独立。
- 不保存账号密码，不自动提交登录协议、验证码、滑块、扫码或设备确认。
- 不读取或上传 Cookie、Token、完整页面、截图、网络响应或客户个人信息。
- 不调用抖店内部未公开接口，不通过网络拦截或远程下发脚本采集。
- 不在首版补历史，也不承诺平台页面未提供的指标。

## 用户任务

数据负责人需要确认抖店昨天的店铺、商品、直播和短视频经营数据是否已完整入库；日常只在登录失效、人工验证、页面变化或报表异常时处理明确的恢复动作。老板和运营在业务 App 中只读取标准事实，不进入抖店页面逐项抄数。

## 设计决策

采用“官方下载优先、固定页面读数兜底”的方案：

- `product_daily`、`live_daily`、`video_daily` 只接受官方明细下载或经过真实页面验证的结构化明细。
- `store_daily` 优先使用官方下载；平台没有明细下载时，允许从固定白名单页面容器读取登记指标。
- 不使用抖店内部未公开接口，不拦截网络响应，不恢复账号密码登录。
- 平台能力分类为“扩展现有能力”：复用共享任务、租约、游标、下载、通知、归档和数据同步 UI，只新增抖店 provider adapter、解析器和标准事实 writer。

## 信息层级

- 主信息：昨天四类资源是否成功、数据截止日、覆盖率、行数和最后可信日期。
- 辅助信息：店铺、任务阶段、来源报表、耗时、批次、错误和恢复动作。
- 低频信息：selector/report version、attempt、文件哈希、历史运行和未来回补范围。
- 不展示：账号密码、Cookie、Token、验证码、绝对路径、完整页面、原始文件和客户个人信息。

## 页面结构

不新增左侧导航。

- “数据接入 → 电商平台”的抖音卡片从“等待文件样例”改为“Chrome 官方报表采集”，状态由真实 adapter readiness 决定。
- “数据同步”复用现有设备、执行记录和异常优先布局，增加抖店四类资源标签与固定恢复动作。
- 店铺运营和数据中心页面通过平台 API 读取标准事实，不直接调用抖店或本机采集器。
- 巨量千川保持独立的“未接入”广告平台卡片，不并入抖店经营采集状态。

## 交互流程

### 正常日计划

1. 05:00 后本机执行器为目标环境和已登记店铺生成四个昨天任务。
2. 插件领取一个任务并探测目标抖店/罗盘标签页的 content script；探测失败时刷新固定页面后再次探测。
3. adapter 校验登录态、店铺身份、页面类型和业务日。
4. 有官方报表时触发导出并等待当前任务文件；`store_daily` 无报表时读取固定白名单指标。
5. 本机解析、日期核对、敏感字段剔除、原始归档和标准化预检。
6. writer 分块写入任务持久化的目标 `businessDb`，完整提交后完成任务并推进资源游标。
7. 数据同步页显示完成时间、行数、覆盖率和最后可信日期。

### 人工恢复

登录、验证码、滑块、扫码或设备确认出现时，任务进入 `waiting_human`。数据同步页显示平台、店铺、资源、公司 Mac 和“打开抖店处理”按钮。员工在同一 Chrome Profile 完成验证后点击“我已处理，重新采集”，只重排原任务资源和业务日。

### 历史回补

首版不启动回补。后续管理员选择起止日期并明确确认后，控制面按平台允许的最大导出区间拆成可恢复任务；交互只设置范围，点击“开始回补”才生成任务。历史任务与日计划使用相同 adapter、解析器、幂等键和质量门槛。

## 组件复用

- 复用 `chrome-extension/company-data-collector` 的 MV3 身份、alarms、downloads、本机桥接和固定任务投影。
- 复用 `scripts/web-data-collector` 的 05:00 调度、租约、重试、下载稳定性检查、通知和原始归档。
- 复用 `/api/platform/v1/web-collection` 的 runner/job/run/cursor/notification 控制面。
- 复用数据同步页的设备卡片、状态徽标、执行记录、失败置顶和人工恢复动作。
- 复用业务数据库选择中间件；经营事实 writer 显式接收 `businessDatabase(context)`，不直接访问 `PRODUCT_FLOW_DB`。
- 不复用旧 `browser_agent_tasks` 抖店账号密码流程；其凭据销毁和归档状态保持不变。
- 不复用 `user_insights` 市场事实表。市场类目/竞品事实与本店经营事实口径不同，只通过稳定商品/店铺维度在读取层关联。

## 新增边界

### 抖店扩展适配器

`chrome-extension/company-data-collector/providers/douyin.js` 负责：

- 固定允许来源：`https://fxg.jinritemai.com`、`https://compass.jinritemai.com` 及真实下载验收确认的官方固定下载来源。
- 四类资源的固定入口、页面分类、日期控件、店铺身份校验、导出动作、报表状态和白名单指标。
- 只输出安全结果：任务 ID、资源、下载 ID/文件名、页面分类、字段版本和安全错误码。

远端任务不能传 URL、selector、脚本、店铺名称、账号或任意报表参数。店铺 ID 和目标环境由服务端任务生成并签入固定 task grant；插件只验证，不接受页面覆盖。

### 本机 provider adapter

`scripts/web-data-collector/providers/douyin/` 负责：

- 资源注册与 05:00 日计划。
- 文件识别、格式验证、编码处理、字段映射、日期/店铺/行数预检。
- 本地原始归档和内容哈希幂等。
- 将标准化事实提交给受控 ingest writer。

### 标准事实 writer

新增 `/api/platform/v1/commerce-facts/ingest`，只接受已登记 runner、provider/resource schema、任务 grant、环境版本、批次哈希和标准事实。服务端重新校验任务、资源、目标环境、storeId、业务日、行数和字段上限后，在一个完整批次内替换对应 `provider + store + resource + businessDate` 的事实。

建议新增四张业务事实表：

- `commerce_store_daily_facts`
- `commerce_product_daily_facts`
- `commerce_live_daily_facts`
- `commerce_video_daily_facts`

表中只存稳定维度、原子事实、来源版本、批次和质量；比例和均值在查询层重算。四张表的展示数据目录策略登记为 `transform_sales`，并提供针对各表的原子事实变换与派生值重算测试。

### 读取 API

新增 `/api/platform/v1/commerce-facts`，支持完整日期范围、provider、storeId、resourceType，以及对应的 productId/liveSessionId/videoId 条件。选择筛选条件不触发请求；调用方点击查询后才读取。响应包含事实、最新日期、最后成功时间、coverage、confidence 和安全状态，缺失值为 `null`。

## 页面状态

- 加载：读取公司 Mac 心跳、四类任务和最近游标。
- 空数据：区分“尚未到 05:00”“该日官方确认无记录”“资源尚未完成真实验收”。
- 错误：区分设备离线、未登录、等待验证、日期未生效、导出生成失败、下载超时、字段变化、店铺不一致、解析失败、业务日不一致和 D1 失败。
- 无权限：可按既有数据权限查看安全状态，不能启停 adapter、重排任务或查看原始归档。
- 禁用：adapter 未完成真实样本验收时显示“尚未接通”，不显示成功。
- 成功：显示资源、业务日期、行数、覆盖率、完成时间和批次；不以页面打开或下载完成冒充入库成功。
- 部分成功：逐资源显示成功与失败，整体状态为“部分就绪”，业务 App 不补齐缺失资源。

## 响应式与钉钉 WebView

沿用数据同步页已有笔记本、窄屏和 390px 单列规则。资源状态在桌面为紧凑表格，在窄屏为按异常优先的卡片。钉钉 WebView 只查看状态和说明；“打开抖店处理”明确提示需到公司 Mac，不尝试控制移动端浏览器。

## 数据流与环境边界

```text
Cloudflare 控制数据库
  └─ web_collection job / run / cursor / runner
          ↓ 固定安全任务
公司 Mac LaunchAgent → MV3 插件 → 抖店/电商罗盘官方页面
          ↓ 下载 ID 或固定白名单指标
本机解析、脱敏、哈希、原始归档
          ↓ 受控 ingest + 任务 grant + 目标环境版本
middleware 选择的 businessDb
  └─ commerce_*_daily_facts
          ↓ 只读 commerce-facts API
数据中心 / 电商店铺运营 / 公司经营
```

控制数据库只管理采集控制面。业务事实只写任务创建时服务端确定的目标业务数据库。浏览器、插件、本机 runner 和 provider 文件都不能指定 binding 或数据库 ID；展示环境版本过期时在投影写入前失败。

## 数据质量与完整性

- 文件任务保存来源报表版本、内容哈希、解析器版本、首尾业务日、来源总行数、有效行数和拒绝行数。
- 页面汇总任务保存 selector version、已找到白名单字段数和必填字段缺失列表，不保存页面正文。
- `coverage` 以必填指标覆盖、来源行覆盖和稳定 ID 覆盖共同计算；`confidence` 为 `high/medium/low`。
- 业务日、店铺、稳定实体 ID或必填原子字段任一关键校验失败时不得 `success`。
- 来源明确无记录允许 `rowCount=0` 且 `confidence=high`；页面加载失败或权限不足时 `rowCount=null`。
- 同一资源的新失败不会删除最后成功事实；读取 API同时返回请求日期状态与最后可信日期。

## 标准事实

### 店铺每日事实

- 维度：provider、稳定 storeId、业务日期、来源版本。
- 原子事实：成交金额、成交订单数、成交人数、用户支付金额、结算金额、退款金额（支付时间）、退款金额（退款时间）、退款订单数（支付时间）、退款订单数（退款时间）、商品曝光人数、商品点击人数。
- 派生值：退款率、客单价、曝光到点击转化率、点击到成交转化率，只在读取时由原子事实重算。

### 商品每日事实

- 维度：provider、storeId、平台商品 ID、可选平台 SKU ID、业务日期。
- 显示字段：商品名称、SKU 名称、商家编码；通过已有商品映射关联共享商品主数据。
- 原子事实：曝光人数、点击人数、成交人数、成交订单数、成交件数、成交金额、用户支付金额、退款订单数、退款件数、退款金额。

### 直播每日事实

- 维度：provider、storeId、稳定直播场次 ID、直播日期、开播/结束时间、可选主播/账号稳定 ID。
- 原子事实：开播时长、曝光人数、进入人数、观看人数、有效观看人数、商品点击人数、加购人数、成交人数、成交订单数、成交件数、成交金额、用户支付金额、退款订单数、退款金额。
- 派生漏斗：曝光→进入→停留/有效观看→商品点击→加购→支付→退款。

### 短视频每日事实

- 维度：provider、storeId、平台视频 ID、发布日期、业务日期、可选账号稳定 ID。
- 显示字段：视频标题/摘要、关联商品 ID、素材 ID；不保存评论正文或用户身份。
- 原子事实：播放人数/次数、有效播放、点赞、评论数、分享、商品曝光、商品点击、成交人数、成交订单数、成交件数、成交金额、退款订单数、退款金额。

所有来源未提供的值写 `null`，不得补 0。官方明确返回 0 条记录时才允许 `rowCount=0`。比例、均值和转化率从原子分子、分母重算。

## 错误处理

新增稳定错误族：

- `DOUYIN_LOGIN_REQUIRED`
- `DOUYIN_HUMAN_VERIFICATION_REQUIRED`
- `DOUYIN_STORE_IDENTITY_MISMATCH`
- `DOUYIN_STORE_DATE_RANGE_NOT_APPLIED`
- `DOUYIN_PRODUCT_DATE_RANGE_NOT_APPLIED`
- `DOUYIN_LIVE_DATE_RANGE_NOT_APPLIED`
- `DOUYIN_VIDEO_DATE_RANGE_NOT_APPLIED`
- `DOUYIN_EXPORT_GENERATION_FAILED`
- `DOUYIN_EXPORT_TIMEOUT`
- `DOUYIN_REPORT_SCHEMA_CHANGED`
- `DOUYIN_REQUIRED_FIELDS_MISSING`
- `DOUYIN_RESOURCE_NOT_COVERED`

错误摘要只说明资源、阶段、业务日和恢复动作，不包含页面文本、平台追踪码、文件绝对路径或业务行内容。

## 安全边界

- 插件新增的 host 权限仅覆盖已确认抖店/罗盘 HTTPS 来源和官方下载来源。
- 不增加 Cookie、History、WebRequest、Debugger、Native Messaging 或密码权限。
- 不保存账号密码，不恢复旧凭据连接；员工自行在公司 Chrome 完成首次登录和人工验证。
- 页面探针只返回代码登记的字段，不返回 `body.innerText`、完整 HTML、截图或网络响应。
- 下载文件先在本机剔除客户姓名、手机号、地址、账号、评论正文和其他个人字段；未登记敏感列出现时预检失败并阻止上传。
- ingest 使用 runner 身份、任务所有权、目标环境版本、provider/resource schema 和内容哈希多重校验。
- 业务 App 只读取标准事实 API，不控制插件、不读取原始文件或运行凭据。

## 兼容、迁移与回滚

- 保持现有快麦 adapter、任务表和本机桥接协议兼容；增加抖店 provider 不改变快麦任务身份。
- 新增 D1 事实表和索引；迁移不修改现有销售、商品、用户洞察和广告事实。
- `douyin-ecommerce` 从 `retired` 变为 `integrating`，只有四类资源逐项完成真实生产验收后才登记相应 capability；不能一次标记全部 connected。
- 新 ADR 覆盖旧店铺文件导入过渡决策：文件导入仍是人工兜底；网页登录采集只复用已登录会话并执行只读官方报表，不恢复凭据自动登录。
- 回滚只关闭 provider 开关和日计划，保留任务、运行、原始归档和最后成功事实；读取层显示 stale，不回退正式库或生成模拟数据。

## 测试策略

- 领域测试：上海时区昨天、四资源计划、storeId 幂等、资源独立游标、历史回补默认关闭。
- MV3 测试：最小权限、固定来源、固定任务字段、页面分类、登录/验证、日期校验、官方导出和白名单读取。
- provider 测试：四种真实报表 fixture、字段别名、日期、店铺、稳定 ID、敏感列、空数据、重复文件和 schema change。
- API/迁移测试：认证、权限、目标 `businessDb`、控制库隔离、批次原子替换、幂等、错误、容量和兼容。
- 展示数据库测试：四张表的 `transform_sales` 目录策略、可加总事实变换、派生比例重算和敏感字段缺失。
- UI 测试：四资源、部分就绪、null 非 0、失败置顶、人工恢复、无权限和响应式状态。
- 真实验收：分别从店铺总览、商品、直播、短视频采集一个昨天样本，核对平台页面/官方文件、本机归档、D1 和数据同步页；生产 readiness 需要 `douyin-ecommerce`、`browser-market-collector`、`cloudflare-pages`、`cloudflare-d1`。

## 验收标准

1. 已登录公司 Chrome 在 05:00 后为昨天生成四个独立任务，重复计划不重复写事实。
2. `store_daily` 仅通过官方下载或固定白名单字段得到昨天汇总，不上传完整页面。
3. `product_daily`、`live_daily`、`video_daily` 分别通过真实官方报表或已验证结构完成下载、归档、预检和 D1 入库。
4. 每个资源至少用一个真实昨天样本核对业务日期、行数、总量和关键指标；平台页面、原始文件、D1 事实和数据同步记录一致。
5. 缺失字段返回 `null`；日期、店铺、稳定实体 ID或必填字段不一致时不标记成功。
6. 登录、人工验证、日期未生效、下载失败、字段变化和 D1 失败均留下运行记录，失败不覆盖最后成功数据。
7. D1、日志、任务、通知和前端不包含账号密码、Cookie、Token、验证码、完整页面、原始文件或客户个人信息。
8. 巨量千川仍显示未接入，抖店自然经营事实不冒充付费投放事实。
9. 首版只运行昨天任务，不创建历史批量回补任务。
